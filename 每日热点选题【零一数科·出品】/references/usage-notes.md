# 信息收集与交付约定

## 待检字段

| 字段 | 必填 | 示例 |
|------|------|------|
| 行业 `industry` | 是 | 美妆 / 食品 / 母婴…（1～64 字符） |
| 品牌关键词 `brand_keywords` | 否 | 兰蔻、小棕瓶（逗号分隔，可多个） |
| 平台 `platforms` | 否 | 抖音、小红书…（不指定=全部平台） |
| 营销目标 `goal` | 否 | 种草（默认）/ 带货 / 品宣 / 引私域 |
| 选题数量 `count` | 否 | 默认 8（范围 5～10） |
| 额外要求 `additional_requirements` | 否 | 「优先口播脚本，避开竞品硬广」（≤2000 字） |

> 除行业外全部可选：缺省走后端默认（goal 种草、count 8、全平台、无额外要求），不阻塞。

## 收集流程

1. 触发 skill 后先判断行业是否给出。
2. **行业已给** → 直接生成（其余缺省用默认），可顺带确认品牌/平台/目标。
3. **行业缺失** → 一次性追问缺失项（只问 1 轮）。话术示例：
   > 技能已就绪 ✅ 帮你出今天的每日热点选题。方便补我几条信息就能开始：
   > 1. **行业**——美妆 / 食品 / 母婴？（必填）
   > 2. **品牌或产品关键词**——如「兰蔻、小棕瓶」（可选，越准越能植入自身产品）
   > 3. **重点平台**——抖音 / 小红书…？（不指定就是全部）
   > 4. **营销目标**——种草 / 带货 / 品宣 / 引私域？（默认种草）
   >
   > 不指定选题数量也行，我默认出 8 条。
4. **仍不给行业** → 不强行开始（行业是必填），再次说明需要行业即可开始；其余字段用默认。

要点：一次问清，不挤牙膏；不展示技术字段名（industry/goal/count 等不出现给用户，转成中文）。

## 调用与重试

- **主路径（异步）**：`POST /api/v1/content/hot-daily/tasks` 立即拿 `task_id` → `GET /tasks/{id}` 轮询 → 终态交付。
- **拆分轮询（WorkBuddy/Web 防会话中断，推荐）**：
  - 创建：`python3 scripts/hot_daily.py --industry "美妆" --only-create`（退出码 0，拿 task_id）
  - 轮询：`python3 scripts/hot_daily.py --poll-task <task_id> --industry "美妆" --out ...`（退出码 13 仍运行，再跑一次；退出码 0 交付报告）
  - ⚠️ `--poll-task` 建议带 `--industry`（与创建时相同），用于报告标题兜底；后端 markdown 已自带标题，不带也能正常交付。
- **默认报告文件**：未传 `--out` 时，脚本自动写当前目录的 `热点日报-<task_id>.md`。
- **实扣字段**：`data.billing.total_points`（字符串）。
- **进度**：脚本 stderr 周期输出，用户中途问「跑到哪了」时读 stderr 最新行转述（status / 已用时 / task_id），不要说「查不了」。
- **失败重试**：若输出含 `HOT_DAILY_TASK_ID` 或 stderr 含 `task_id=`，用户同意后执行 `--retry-task <task_id> --out ...`。
- **幂等**：同一次用户意图的重复提交尽量用同一 `--idempotency-key`；用户说「刚才那次再提交」且你持有上次 key 时复用。

## 交互节奏

- **收集**：最多 1 轮追问，之后用默认继续，不让用户反复等待。
- **扣点确认（硬性，跳过不得）**：跑脚本**前**必须告知「本次任务较复杂，预计扣点约 12 点，实际扣点视任务复杂程度而定、以最终完成任务时的实际点数为准，是否继续？」，用户**明确确认**后才跑脚本。
- **速度差异**：说明本次大约耗时（如「全量约 1～2 分钟，期间 stderr 会有进度」）。用户问进度时转述 stderr，勿空等不回。
- **交付**：日报 MD 一次性渲染给用户（务必把分隔符之间的 Markdown 真正渲染出来，不能只甩文件路径或贴带 `\n` 的原始文本）。
- **成功后**：告知实际扣除点数 + 报告查看方式（已渲染在上方 + 已存为 MD 文件）。
- **失败后**：告知「因网络原因本次任务执行失败，相应点数已返还」；有 task_id 时询问是否用 `--retry-task` 重试。
- **交付后**：主动询问是否需要就某条选题深入展开（如「要不要我把某条选题扩成完整口播脚本」），可衔接其他 skill。

## 免责声明（交付报告时附一句）

- 热点榜单与热度数据由后端实时采集，可能存在采集时延与平台口径差异，**时效性强，建议尽快落地**，过期需重新生成。
- 选题推荐与「相关度/综合分」为**模型参考判断，不承诺精确**，仅作选题灵感，正式发布前建议人工复核合规与品牌调性。
