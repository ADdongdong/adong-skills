# docx 脱敏换牌（公司名替换 + 涉密信息脱敏）

## 适用场景
- 有一份 A 券商的部署/操作手册（docx），要改出 B 券商的 POC/交付版。
- 需把原公司名替换为新公司名，并把 IP、端口、账号密码、密钥、内部主机名等全部脱敏为 `xxx`。
- 注意：本技能只处理**文本层**（段落、表格、页眉页脚、文本框）。**嵌入的图片（截图）无法脱敏**，必须单独提示或人工处理。

## 关键陷阱（必看，否则会漏替换）
1. **IP 被拆分到多个 run**：Word 里 `10.60.157.113` 常常存成 `10.60.157.11` + `3` 两个 `w:t`。逐 `w:t` 替换匹配不到完整 IP，会整批漏掉。
   - ✅ 解决：按**段落**合并所有 run 文本 → 脱敏 → 写回首个 run、清空其余 run（`runs[0].text = new; for r in runs[1:]: r.text=""`）。
2. **中文吃掉 `\b`**：Python `re` 的 `\b` 把 CJK 当单词字符。所以 `端口默认是3100` 里的 `3100` 因前接「是」而无词边界，正则 `\b3100\b` 匹配不到。
   - ✅ 解决：端口用 `(?<![\d.])端口(?![\d.])` 边界（仅禁止数字/小数点作相邻字符），不要用 `\b`。
3. **目录域代码 `_Tocxxxx`** 里含 `80` 等数字，用上面的负向后顾即可避免误伤。
4. **保留项（不要脱敏）**：产品名（Nacos/THS/BES/达梦）、厂商名（西点信息/West Point，即出品方）、数据库账号名（如 `forphz`，属账户非密码）、默认 identity key/value（产品默认值）、授权文件名。只脱敏真正的 IP/端口/密码/密钥/主机名。

## 标准流程
1. 先扫描确认替换范围：
   - `grep` 文档正文（及 `document.xml`）确认原公司名出现位置；本例会只在标题出现 1 次（其余在图片里）。
   - 列出所有真实 IP（如 `10.60.157.x`、回环 `127.0.0.1`）、端口（`8848/7848/9848/9849/6900/8800/8000/4900/3100/15236/80/443`）、密码（`admin/B#...`、`nacos/nacos` 仅脱敏密码半边）、密钥（长串 `SecretKey...`）、内部主机名（`sv-xxxx`）。
2. 写脚本：
   - 用 `python-docx` 遍历 `doc.paragraphs`、所有 `table` 单元格段落、`section.header/footer`（含 first_page/even_page）的段落与表格，做**段落级合并替换**。
   - 再对 `doc.element` 做一层逐 `w:t` 兜底（处理文本框等未纳入段落枚举的内容；已是 `xxx` 不会二次变化，幂等安全）。
   - 更新 `core_properties.title` 里的公司名。
3. 保存为新文件。
4. **必须核验**：重新读 `document.xml`，确认 (a) 原公司名=0、(b) 残留 IPv4=0、(c) 各密码/密钥特征串=0、(d) 端口非 TOC 残留=0。
5. **必须提示图片风险**：统计 `word/media/` 下图片数，明确告知用户截图未脱敏，需人工/OCR 处理后再外发。

## 输出
- 新 docx 文件（公司名已换、文本层涉密信息全 `xxx`）。
- 给用户的提醒：图片未脱敏 + 建议处理方式（人工涂抹 / OCR 定位后模糊 / 换占位框）。

## 反例（不要这样做）
- ❌ 只做 `paragraph.text = paragraph.text.replace(...)` —— python-docx 不支持直接赋值 `.text` 且会丢格式。
- ❌ 只遍历 `w:t` 做 `t.text.replace` —— 漏掉跨 run 拆分的 IP，整批 .113~.119 全漏。
- ❌ 端口用 `\b` —— 中文前接的端口（如 3100）漏替换。
