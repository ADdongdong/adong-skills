# 02 需求点模板（四段式）

> 本文件是规范的核心。每个功能点（H4）下面按 H5 挂四个小节，**顺序固定**，无内容的小节可整段省略，但不要调换顺序。

```
H4  功能点名称（与【菜单目录】的菜单/页面一一对应，如：首页－底稿待办）
  H5 用户场景      1~3 句业务口吻的场景描述，讲清楚"谁、在什么情况下、要解决什么"
  H5 权限说明      菜单权限 / 功能权限 / 列表数据权限 / 使用人员；有角色×状态矩阵时补表
  H5 功能描述      数据来源 → 状态划分 → 操作说明(表) → 界面原型图 → 字段逻辑
  H5 补充说明      编号列表；无则写"无"
```

实测词频（v4.0.5）：`用户场景` 67 次、`功能描述` 60 次、`权限说明` 59 次、`补充说明` 46 次。四段式是绝对主流；偶见用 `功能权限`/`功能说明` 代替 `权限说明`/`功能描述`，同一份文档内应统一。

## 三种挂载层级（按功能点粒度选，全文档统一）

| 场景 | 结构 | 实例 |
|---|---|---|
| **单页功能点**（大多数） | `H4 功能点 → H5 四段式` | `首页－底稿待办` → 用户场景/权限说明/功能描述/补充说明 |
| **多页模块**（一个模块下含多个并列页面） | `H4 模块 → H5 页面 → H6 四段式` | `工作底稿权限维护` →（H5）`监管账号项目授权` / `授权查阅底稿管理` / `授权借阅底稿管理` / `分管底稿授权` / `底稿创建人权限管理` → 各带 H6 四段式 |
| **定制化需求·功能需求章**（一级菜单本身即需求） | `H3 需求名 → H5 四段式`（跳过 H4） | `H3 未报送统计` → H5 用户场景（源文档即如此） |

> 实务判断：一个模块下若每个页面都要单独写权限和按钮，用"多页模块"；若整章按"一条需求一个功能点"组织（定制化需求），用 H3。

## 一、用户场景

**写法**：一段或几段普通段落，不标题、不加"用户场景："前缀。业务语言，讲清场景与目的。

原文示例（首页－底稿待办）：
> 为当前登录用户提供底稿待办处理，并可通过待办详情查看并处理项目的底稿任务待办。

原文示例（项目列表，多句）：
> 系统提供项目创建、删除、查询功能，以便于项目业务人员或综合管理部人员管理项目。
> 系统提供以部门维度、所有项目维度、分管项目维度的项目数据查看权限，以便于部门负责人、投行委领导可按照数据权限查看投行项目数据。
> 系统提供监管权限分配后，可通过我的项目查看监管账号授权的项目权限

原文示例（首页－快捷操作，编号式）：
> 1.项目业务人员或综合管理部人员创建项目管理项目。

## 二、权限说明

**固定四要素，按其出现顺序**（缺项可省）：

```
菜单权限：<谁能看到这个菜单>
功能权限：维护－包括：新建、下载样本、导入项目、查询、项目详情。可支持按照系统角色进行授权…
          查看－包括：查询、项目详情。…
          删除－…
列表数据权限：<能看哪些数据，按角色分别写>
使用人员：<角色名>
```

**单角色时写成一行**（原文）：
> 菜单权限：登录用户均有首页权限
> 功能权限：不涉及
> 列表数据权限：所有需要当前登录用户处理的底稿目录
> 使用人员：系统管理员

**多角色时标签独占一行、随后逐条列角色**（原文 · 项目列表）：
> 菜单权限：
> 我的项目－普通业务人员拥有该菜单权限。
> 本部门项目管理－作为部门负责人拥有该菜单权限。
> 所有项目管理－作为投行分管领导、质控领导等拥有该菜单权限。
> 分管项目管理－作为投行分管领导拥有该菜单权限。
> 功能权限：
> 维护－包括：新建、下载样本、导入项目、查询、项目详情。可支持按照系统角色进行授权，需要满足给到菜单权限的人可进行维护。
> 查看－包括：查询、项目详情。支持给到菜单权限的人员可查看项目列表信息，通过查询条件进行查询。
> 删除－支持给到权限的人员可进行项目创建后删除，一般给到超级管理员。
> 列表数据权限：
> 我的项目－作为项目成员可查看项目信息
> …

**无权限约束时**统一写：`菜单权限：不涉及` / `功能权限：不涉及`。

**角色 × 状态矩阵**（当权限随项目状态变化时补一张表，放在权限说明段末尾）：
表头 `角色/项目状态 | 正常 | 终止 | 完成`，单元格填可执行的动作，不可执行填 `/`。

## 三、功能描述

**二级要素顺序固定**：`数据来源 → 状态划分 → 二级页面 → 操作说明 → 界面原型图 → 字段说明/字段逻辑`。没有的写"无"或整段省略。

> `二级页面` 与 `字段说明` 非源文档固有小节名，是整理"一个菜单下挂多个并列页面"或"字段较多需单列"时的规范写法（表头用 `二级页面 \| 规则/说明`、`字段名称 \| 规则/说明`），保持与源文档其余部分不冲突即可。

### 3.1 数据来源
- 单条：`数据来源：底稿详情页所有需处理的底稿目录`
- 多条：`数据来源：` 换行后逐条列
  ```
  支持与投行项目管理系统对接获取项目信息
  支持手动创建项目
  ```
- 涉及配置菜单时写清路径（原文）：
  > 配置菜单：工作底稿基础维护－工作底稿模型维护－项目角色维护
  > 数据来源：底稿系统进行项目新建，填写相关项目人员数据；与投行系统对接，获取投行项目信息数据

### 3.2 状态划分
- 无：`状态划分：无`
- 有：标签独占一行 + 逐条列状态说明，或跟一张 `状态类型 | 状态说明` 表。原文示例：
  > 状态划分：
  > 与投行对接项目状态与投行系统保持一致
  > 手动创建项目时，项目状态分为：
  + 表 `状态类型|状态说明`：正常 / 完成 / 终止

### 3.3 操作说明（★ 最核心）
固定格式：先写一行 `操作说明：`，紧跟一张三列表：

| 名称 | 类型 | 规则/说明 |
|---|---|---|
| 待办详情－待办 | 按钮 | 点击后进入对应项目的需提交待办详情页 |
| 提交 | 按钮 | 勾选需要提交的底稿目录，点击提交按钮可进行提交操作 |
| 上传附件 | 按钮 | 可在待办列表中上传底稿目录的附件 |
| 更多操作 | 下拉选择 | 可进行底稿目录索引、附件引用、引用流程、引用底稿、填写说明的操作 |
| 查看索引详情 | 按钮 | 点击可以查看底稿目录的索引详情信息 |
| 更多 | 下拉选择 | 可进行下载、预览的操作 |
| 替换 | 按钮 | 点击可替换底稿目录文件 |
| 删除 | 按钮 | 上传后未提交的文件可进行删除的操作 |

要点：
- **排布顺序 = 页面视觉顺序**：工具条按钮 → 搜索区 → 列表"操作列"图标 → 弹窗内按钮；
- `名称` 用界面上的原始文案；同一名称出现在不同位置时加位置前缀（`操作列－删除`、`待办详情－待办`）；
- `规则/说明` 写交互结果，不写技术实现；有弹窗/二次确认要写明（"弹出框询问用户是否删除"）；
- 表格数量随需求复杂度变化，常见 2~29 行。

### 3.4 界面原型图
固定写法：`界面原型图：` 或 `界面原型图` 单独一行，随后插入页面截图（多张时每张上方用"列出段落1"样式写图注，如 `快捷操作图标：`、`我的借阅页面：`）。
无图时写 `界面原型图：无`。

### 3.5 字段逻辑
写字段的取值/校验/联动规则。简单时 `字段逻辑：不涉及`；复杂时用小标题 + 表格（`字段名称 | 字段说明` / `字段名称 | 规则/说明`）。

## 四、补充说明

- 无：`无`
- 有：编号列表，逐条写边界情况、限制条件、后续规划。原文示例（签字人员统计）：
  > 1、需要通过此底稿文件，关联查出项目相关信息。
  > 2、通过项目信息关联查询项目成员的利益冲突信息。
  > 3、通过识别功能，查出签字人员、未走利益冲突的签字人员信息。
  > 4、签字文件在指定的底稿目录下上传，ocr识别的时候要支持可配置模版目录…
