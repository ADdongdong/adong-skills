## 二、正文直接格式（★ 光靠样式不够，主文档全靠直接格式控制排版）

主文档正文段落**不使用样式默认值**，而是逐段写死直接格式。要让新写的段落与主文档视觉一致，必须照抄下列参数（实测自 v4.0.5 的 3187 个段落）：

| 元素 | 段落级（pPr） | 字符级（rPr） |
|---|---|---|
| **普通正文段落** | `<w:spacing w:line="360" w:lineRule="auto"/>`（1.5 倍行距） | `<w:rFonts w:ascii="宋体" w:hAnsi="宋体" w:eastAsia="宋体" w:cs="宋体" w:hint="eastAsia"/>` + `<w:sz w:val="24"/>`（12pt） |
| **用户场景正文** | 同上 + `<w:ind w:firstLine="420" w:firstLineChars="0"/>`（首行缩进 2 字符） | 同上 |
| **各级标题** | `<w:spacing w:line="360" w:lineRule="auto"/>` | 仅 `<w:rFonts w:hint="eastAsia"/>`（**不要**覆盖字体字号，交给 heading 样式） |
| **表格单元格** | `<w:spacing w:before="0" w:after="0" w:line="360" w:lineRule="auto"/>` | 同上（宋体 12pt） |

要点：
- 行距最关键。样式默认不是 1.5 倍，**每个段落都要显式写 `line=360`**，否则间距明显偏紧。
- 正文字体要连 `w:ascii` 一起设成宋体；只设 eastAsia 会导致数字/英文落到样式里的 Calibri，肉眼可见不一致。
- 标题不要设 `sz`/`rFonts ascii`，否则会顶掉 heading 样式定义的字号字体层级。
- 缩进只有「用户场景」正文需要（首行 420 twips）；权限说明、功能描述、补充说明的条目**不缩进**（主文档即如此）。
- 脚本里对应 `fmt_para()` / `fmt_run()` 两个 helper，`req()` 已对用户场景自动加缩进。


## 三、标题多级自动编号（关键）

- 所有 `heading 1..6` 共用 `numId=1`（`abstractNumId=30`），层级 `ilvl=0..5`。
- 编号格式（`numFmt=decimal`）：

| ilvl | lvlText | 效果 |
|---|---|---|
| 0 | `%1.` | `1.` |
| 1 | `%1.%2.` | `1.1.` |
| 2 | `%1.%2.%3.` | `1.1.1.` |
| 3 | `%1.%2.%3.%4.` | `1.1.1.1.` |
| 4 | `%1.%2.%3.%4.%5.` | `1.1.1.1.1.` |
| 5 | `%1.%2.%3.%4.%5.%6.` | `1.1.1.1.1.1.` |

**因此**：标题文字里**绝对不要手写"1.1"这类序号**，序号由样式自动生成；插入/删除章节后编号自动重排。若某个标题出现在目录之外（如封面、题注）却被套了 heading 样式，会导致后续编号错位——用 Normal 样式。

## 五、表格版式约定

- 一律使用 `Table Grid` 样式，**并且每张表再显式写一遍 `tblBorders`**（见下）。
- 列宽合计不超过正文区宽度（A4 纵向减去左右页边距，约 15 cm）。
- 采用「固定列宽 + 表宽 100%」：`tblW type=pct w=5000`、`tblLayout type=fixed`，并同步写 `tblGrid` 的 `gridCol` 宽度，否则 Word 会按内容重排列宽、导致同一文档内表格宽窄不一。
- 表头行可加浅底纹（`DCE6F1` 一类）便于区分，非强制。
- 长表格允许跨页，不要手动拆表。

### 5.1 **每张表都必须有框线**（v1.1 明确）

```xml
<w:tblBorders>
  <w:top w:val="single" w:sz="4" w:space="0" w:color="auto"/>
  … left / bottom / right / insideH / insideV 同上
</w:tblBorders>
```

理由与坑：

1. **模板里的【菜单目录】表本来是没有边框的** —— 它的 `tblBorders` 六向全是 `w:val="none"`。而**直接格式优先于样式**，所以光给它套 `Table Grid` 样式**不会**出现框线，必须把 `none` 换成 `single`。
2. 文档里同时存在"样式给的框线"和"直接格式给的框线"，某张表被复制粘贴过之后就无法推断应该是什么样 —— 所以统一**收尾时给每一张表写死**，不再依赖样式。
3. `sz=4`（0.5pt）与主文档表格一致；`sz=6` 会明显偏粗。
4. 顺序要求：`w:tblBorders` 在 `tblPr` 里必须排在 `w:tblLayout` / `w:tblCellMar` / `w:tblLook` **之前**（完整顺序见第八节）。

## 六、图片与图注

### 6.1 图注

- **写在图片上方**（主文档即如此），样式用 `列出段落1`（styleId 25），**冒号结尾**：
  `查询结果：`、`我的借阅页面：`、`界面原型图：`、`回函管理数据流转路径：`。
- **不要写「图 4.5-1」这类手写图号** —— 标题编号是样式自动生成的，手写图号在插删章节后必然对不上。
  需要用图号引用时，改为描述性表述（「见下方数据流转图」/「见 5.2」）。
- 图片本身单独一段、**居中**，不写任何说明文字；图下的补充说明另起一段（普通正文）。

### 6.2 尺寸（v1.2 明确）

| 约束 | 值 | 为什么 |
|---|---|---|
| 最大宽度 | **15 cm** | A4 纵向正文区宽度（左右页边距各 ~2.5cm） |
| 最大高度 | **20.5 cm** | 单页可用高度余量（29.7 − 上下页边距 − 图注 − 行距） |

**双向封顶、取更严的那一个**：先按 15cm 宽算高度，若超过 20.5cm，就**改按高度反算宽度**。
实测教训：`flowchart TB` 的长链路图宽高比能到 **1:1.8**（2033×3785 px），按 15cm 宽铺开是 **27cm 高** ——
一张图横跨两三页，读者要翻页对照，等于白画。反过来也别为了塞下而无限缩宽（字会小到读不出）。

### 6.2.1 差于 1:2.2 的图：**先拆成上下两张**

按页高封顶会让又高又瘦的图变得又窄又小，**字号跟着一起缩** —— 这是最容易交付出去的一张"废图"：

| 图宽高比 | 整张按规范铺出来 | 图源 16px 字号变成 | 拆成上下两张后 |
|---|---|---|---|
| **1:2.35**（实测：4.5.2 数据流转路径，2448×5744） | 8.7cm × 20.5cm | **≈4.7pt —— 读不出** | 11.1cm 宽 / 15cm 宽，字 ≈**7.4pt / 9.3pt** ✓ |

```bash
python scripts/split_image_for_docx.py <图.png>          # → <图>_top.png / <图>_bottom.png
```

- 切线**自动挑最靠近中部的空白带**（按每行的墨量轮廓找，并**避开方框的横边框**）；
  判据不能用"整行纯白"—— 纵向流程图每行都有竖线箭头穿过，一条"全白行"都找不到；
- 切线允许穿过一根竖向箭头（表现为上下各留一小截），但**绝不切进方框**（方框有浅色填充，
  墨量很高，天然被排除）；
- 拆完的图注写「回函管理数据流转路径（上半：…）」「（下半：…，接上图）」；
- 拆不出合适切线（图太密）时脚本会明说，这时只能改图源（缩小字号 / 把一条长链路拆成两张图）。

> 顺带：纵向图用 `flowchart TB`，**不要用 `LR`** —— 长链路在 `LR` 下会得到约 **11:1** 的极端宽高比，
> 横向铺满一页时字号小到不可读。

### 6.3 图源：Markdown 的 mermaid 图 → PNG → Word

```bash
# 1) 渲染（skill `mermaid转图片`；输出按 md 中出现顺序命名 mermaid_0/1/2…）
python ~/.codebuddy/skills/mermaid-doc-rendere/scripts/render_mermaid.py <md> --out <图目录> --format png --scale 3
# 2) 生成 docx 时按名字引用
('fig', dict(图注='回函管理业务数据分工（AI 读取 / 人工定性 / 系统推导）', 图片=r'…/figures/mermaid_0.png'))
```

- **`--scale 3`**（2 倍也行，别更低）：最终按 ≤15cm 铺开，像素越多打印越清；
- **图与 md 章节的对应关系要写进脚本注释**（`mermaid_0 = 4.5.1 …`）—— 名字里没有语义，
  过两周就没人知道哪张是哪张；
- **改了 md 里的图必须重跑渲染**，脚本不会自己发现图变了；
- 体积参考：3 张 `--scale 3` 的图约 1.0 MB（docx 从 94KB 涨到 1.07MB），可接受；若图很多再降到 `--scale 2`；
- 图片缺失时插灰色占位 `[图表未找到：<路径>]` 并打印警告，**不让整篇文档生成失败**。

### 6.4 截图要求

- 能看清字段名与按钮文案；涉及数据的截图先脱敏。
- 截图位在需求 Markdown 里用 `📷 图 <章节号>-<序号>` 占位（写清「应展示什么 / 重点可见哪些元素 /
  状态要求 / 对应哪段正文」四件事），补图时替换为 `![图 X-Y](路径)` 并同步 `req()` 的 `界面原型图`。

## 八、元素顺序（改 XML 时最致命的坑）

OOXML 对每个复合元素**子元素的顺序有硬性要求**。顺序错了 Word 打开会报"文档已损坏"，
而且 **python-docx 完全不校验**（能保存、能读回、看起来一切正常）—— 只有用户打开那一刻才炸。

因此**不要用 `parent.append(el)` 添加这些元素**，必须插到规定位置（`insert` 到正确的后继元素之前）：

| 元素 | 必须排在 | 之后/之前的邻居 |
|---|---|---|
| `w:numPr`（段落编号） | `w:pPr` 里 | 在 `w:spacing`、`w:ind`、`w:jc`、`w:rPr` **之前**；在 `w:pStyle`、`w:widowControl` **之后** |
| `w:tblW` | `w:tblPr` 里 | 在 `w:jc`、`w:tblInd`、`w:tblBorders`、`w:tblLayout` **之前** |
| `w:tblBorders` | `w:tblPr` 里 | 在 `w:tblLayout`、`w:tblCellMar`、`w:tblLook` **之前** |
| `w:updateFields` | `w:settings` 里 | 在 `w:hdrShapeDefaults`、`w:footnotePr`、`w:endnotePr`、`w:compat`、`w:rsids` **之前** |

`tblPr` 完整顺序：
`tblStyle → tblpPr → tblOverlap → bidiVisual → tblStyleRowBandSize → tblStyleColBandSize → tblW → jc → tblCellSpacing → tblInd → tblBorders → shd → tblLayout → tblCellMar → tblLook → tblCaption → tblDescription → tblPrChange`

`pPr` 里与本规范相关的部分：
`pStyle → keepNext → keepLines → pageBreakBefore → framePr → widowControl → numPr → … → tabs → … → spacing → ind → … → jc → … → rPr → sectPr`

> 现成的做法：`scripts/build_req_spec.py` 里 `_tbl_pr_set()` 按 `TBLPR_SEQ` 插、`ppr.get_or_add_numPr()`
> 用 python-docx 的 ZeroOrOne（自带 successors）、`w:updateFields` 以 `w:compat` 为锚点 `addprevious()`。
> 顺带提醒：python-docx 1.2 只给 `tblStyle`/`tblLayout`/`jc`/`bidiVisual` 提供了 `get_or_add_*`，
> **`tblW`/`tblBorders` 没有** —— 自己按序插。

## 九、常见格式事故

| 现象 | 原因 | 处理 |
|---|---|---|
| 标题序号乱/重复 | 手写了序号，或正文段落被套了 heading 样式 | 删掉手写序号；正文改回 Normal |
| 表格宽窄不一、超出页边距 | 未设固定列宽与 tblGrid | 按第五节设置 |
| **某张表没有框线**（尤其菜单目录表） | 该表自身的 `tblBorders` 是 `val="none"`，直接格式盖过 Table Grid 样式 | 显式重写 `tblBorders`（见 5.1） |
| 目录里显示别的文档的条目 | 模板 TOC 域的**缓存结果**没清 | 清空域内条目（保留 begin/instrText/separate/end），再置 updateFields（见第十一节） |
| 目录打开不刷新 | 没置 `w:updateFields` | settings 里加 `<w:updateFields w:val="true"/>`，域起点再加 `w:dirty="true"` |
| 出现"● 1、xxx"两层标记 | 条目里留着原来的手写序号 | 加圆点时一并去掉（见第十节） |
| 字体被替换 | 用了新样式或直接设 run 字体 | 只继承模板样式，不覆盖字体 |
| Word 报"文档已损坏"、python-docx 却一切正常 | 元素顺序错（第八节） | 按第八节的顺序插元素；生成后跑一遍顺序自检 |

## 十、项目符号（列表）

**逐条并列的内容一律用真实项目符号**，不要手打"●"、不要用全角空格伪造缩进。

- **定义从哪来**：模板 `numbering.xml` 里已经有几十个 `numFmt=bullet` 的定义（`singleLevel`，`ilvl=0`），
  符号用 Wingdings 字符：`\uf06c`=实心圆 ●、`\uf0d8`=方块、`\uf0b2`=方点；缩进统一 `left=420 hanging=420`。
  **优先挑实心圆**（中文商务文档惯例），脚本 `_find_or_make_bullet()` 就是按这个优先级找的。
- **段落怎么写**：用 `Normal` 样式 + `pPr/numPr`（`ilvl=0` + `numId=<那个 bullet 的 numId>`）。
  行距仍写 `line=360`；**不要再写 `ind` / `firstLine`** —— 缩进由 numbering 定义提供，两处都写会打架。
- **用在哪些内容**：`权限说明`、`补充说明`、`功能描述` 里的 `数据来源` / `状态划分` / `字段逻辑` 多条目、
  以及段落级清单（"本章节暂未收录的需求"那类）。
- **两条不加的口径**：
  1. **用户场景不加** —— 它是叙述性段落（首行缩进 2 字符），加了圆点会被读成清单，反而不像"场景"；
  2. **只有一条时不加** —— 「● 无」「● 不涉及」这种一个圆点带两个字的排版很怪，写成一句话即可。
- **手写序号要去掉**：条目原来的 `1、2、3、` 与圆点会叠成两层标记（"● 1、…"）。若某条序号**被正文引用**
  （"见第 4 点"），那一条改用普通段落写，别加圆点。
- **限制**：模板的 bullet 定义是 `singleLevel`，只有 `ilvl=0`（**没有二级列表**）。需求文档里用平铺的一级列表即可；
  真要二级得自己新建 abstractNum，不建议。

## 十一、目录（TOC 域）自动更新

**域的结构**（模板里已存在，不要删域）：

```xml
<w:fldChar w:fldCharType="begin"/>            ← 加 w:dirty="true"
<w:instrText> TOC \o "1-3" \h \u </w:instrText>
<w:fldChar w:fldCharType="separate"/>
   …（缓存结果：每条目一段，含 HYPERLINK + PAGEREF 子域）…
<w:fldChar w:fldCharType="end"/>
```

**三个要点**：

1. **必须清掉模板带来的缓存结果**。模板的目录域里缓存的是**另一份文档**的条目
   （"1. 引言 / 1.1 编写目的 …"），不清的话，凡是不自动更新域的阅读器（在线预览、部分 WPS）
   打开就会显示这些**与本文档无关**的内容 —— 比空目录更容易让人以为文档错了。
2. **缓存跨段，且首条与域起点同段、末段与域终点同段** —— 要分三处清：域内独占的整段整段删、
   起点段删 `separate` 之后的、终点段删 `end` 之前的（保留该段与它的 `pPr`）。
3. **配平域用深度计数**（`begin` +1 / `end` −1 归零即本域）。**不要"往后找第一个 end"** ——
   域里嵌着 HYPERLINK / PAGEREF 子域，第一个 `end` 是子域的。

**让它自动更新**：域起点加 `w:dirty="true"` + settings 里置 `<w:updateFields w:val="true"/>`
（位置见第八节）→ Word / WPS 打开文档时即按当前正文重排目录，**不需要手动 F9**。
读者若用不更新域的阅读器，才回退到手动 F9。

**收录层级**：模板是 `\o "1-3"`（目录只到 H1/H2/H3，即"大板块 / 端别 / 一级功能模块"，
**H4 功能点不进目录**）—— 与主文档口径一致，默认保持不变。若希望 H4 功能点也进目录，
把开关改成 `\o "1-4"`（脚本里传 `SPEC['目录层级'] = '1-4'`）。
