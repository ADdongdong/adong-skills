# 01 文档整体结构

## 一、文档级要素（顺序固定）

| 顺序 | 要素 | 说明 |
|---|---|---|
| 1 | 封面 | 空行 ×4 → 系统名 → `需求说明书vX.Y.Z` → 空行 → `西安西点信息技术有限公司` → `YYYY年M月`；右对齐/居中按原文档；样式用"文档日期" |
| 2 | 文档修改历史 | 表：`版本号 \| 修改日期 \| 编写人 \| 评审人 \| 批准人 \| 修改内容`（6 列，第 2 行起填） |
| 3 | 编写说明 | 3 条固定文字，原样保留 ↓ |
| 4 | 目录 | TOC 域（WPS/Word 中 F9 更新） |
| 5 | H1 菜单目录 | 表：`一级菜单 \| 二级菜单 \| 三级菜单`（52 行 × 3 列） |
| 6 | 正文 | 见下 |

**编写说明（固定 3 条）**
1. 业务部门编写本需求说明文档之前，新增功能需求需要与需求建设部门对需求的描述和验收标准进行过邮件确认。
2. 本文档蓝色斜体字都是注释或举例，供业务人员编写业务需求参考。
3. 本《业务需求说明书》适用于各种不同类型的业务需求。填制时可根据需求的不同情况在下列章节中裁减。

## 二、【菜单目录】维护规则

- 三列表，`一级菜单 / 二级菜单 / 三级菜单`；**同级重复值留空**（合并单元格的视觉效果靠留空实现），例如"项目管理"只在首行写一次，其下二级菜单的第一列留空。
- 菜单命名与正文 H3/H4 一一对应；差异项在菜单名后用括号标注，例如 `各业务条线项目查看（开源）` 表示定制菜单、`以开源非信创版本菜单为准` 表示沿用旧版。
- **正文每个 H4 功能点都必须能在本表找到落点；表里有而正文没有的，说明需求尚未编写**（这是发现文档缺口的自检手段）。

## 三、正文三大章（H1）

### H1 底稿系统标准产品需求
```
H2 底稿3.0升级4.0变化概览        ← 版本升级说明（非功能点，H3 为"界面交互优化/功能升级优化"，H4 为变化点）
H2 WEB端需求
    H3 首页 / 项目管理 / 工作底稿管理 / 底稿统计分析 / 底稿运维分析 /
       工作底稿基础维护 / 底稿任务委托 / 系统设置
        H4 功能点（页面级）
            H5 四段式
H2 助手端需求   H3 登录页 / 我的项目 / 传输 / 正在下载 / 传输完成
H2 手机端需求   H3 登录页 / 待办事项（→ H4 待办事项－列表 / 详情页-执行人 / 详情页－审核人 …）
H2 客户端需求
```

### H1 自律报送系统标准产品需求
```
H2 WEB端需求
    H3 首页 / 项目报送管理 / 常规报送统计分析 / 常规报送记录 /
       常规报送记录列表—详情页 / 首页-专项报送快捷操作 / 常规文件 …
        H4 功能点 → H5 四段式
```
> "首页"下允许二级页面层级，如 `H4 首页-常规报送 / 项目人员更新报送 / 项目底稿目录报送 / 项目负面事项报送 / 公司负面事项报送`。

### H1 定制化需求
```
H2 定制化需求引言
    H3 编写目的
    H3 项目背景
H2 需求总览      表：条目 | 需求名称 | 新系统主要落点
H2 系统对接需求
    H3 <对接系统>        正文格式：
      模块：<模块名>
      需求说明：
      <逐条说明>
H2 功能需求
    H3 <需求名称>
       H5 用户场景 / 功能权限 / 功能描述 / 补充说明
```

**定制化需求的两个特殊约定**
1. `需求总览`表条目编号形如 `1.0`、`2.0`…，第 3 列写"新系统主要落点"（落地到产品哪个功能），用于向客户说明"定制项在标准产品里怎么落"。
2. 每个需求下可标注原文出处，固定句式：`定制需求梳理清单原始条目（第 4 部分）`。

## 四、编号与层级对照（自动编号，勿手写）

| 层级 | 语义 | 示例 |
|---|---|---|
| H1 | 大板块 | `1. 菜单目录` / `2. 底稿系统标准产品需求` / `5. 定制化需求` |
| H2 | 端别 / 大类 | `2.1 WEB端需求` |
| H3 | 一级功能模块 | `2.1.1 首页` |
| H4 | 功能点（页面级） | `2.1.1.1 首页－底稿待办` |
| H5 | 四段式小节 | `2.1.1.1.1 用户场景` |
| H6 | 段内细分（如"操作说明"下的子项） | 较少使用 |

## 五、裁剪规则

- 项目只涉及底稿 → 只保留 `H1 底稿系统标准产品需求` + `H1 定制化需求`；
- 无定制内容 → 删掉整个 `H1 定制化需求`；
- 无移动端 → 删 `H2 助手端需求` / `H2 手机端需求`；
- 变化概览仅 3.0→4.0 这类大版本升级时写，小版本迭代不写；
- 裁剪只删章节，**不要改章节名、不要重排顺序、不要重编序号**（序号自动）。
