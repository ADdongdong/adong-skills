# 04 表格与词汇库

> 全部取自 v4.0.5 实测统计，写需求时**优先从中选词**，保证术语一致。

## 一、明细表（最高频，112 张表 / 281 个"按钮"条目）

### 1.1 操作说明表 —— `名称 | 类型 | 规则/说明`
用于页面按钮、图标、列表操作、二级页面元素。

### 1.2 同构表头变体
| 表头 | 出现次数 | 适用场合 |
|---|---|---|
| `名称 \| 类型 \| 规则/说明` | 100 | 通用（首选） |
| `操作名称 \| 类型 \| 规则/说明` | 12 | 纯操作清单 |

### 1.3 `类型` 列标准词表（按实测频次）

| 词 | 频次 | 用法 |
|---|---|---|
| 按钮 | 281 | 工具条/弹窗内的按钮 |
| 图标 | 51 | 页面上的独立图标（如快捷操作区） |
| 操作列 | 14 | 列表最右"操作"列的入口 |
| 右键操作 | 14 | 树/目录的右键菜单项 |
| 列表图标 | 14 | 列表行内的图标 |
| 列表超链接 | 6 | 列表中的可点击文字 |
| 操作图标 | 5 | 行内操作图标 |
| 列表操作 | 4 | 列表操作项 |
| 操作列连接 | 4 | 操作列超链接（原文用"连接"） |
| 操作列图标 | 3 | 操作列的图标 |
| 列表链接 | 3 | 列表内链接 |
| 下拉菜单 | 3 | 顶部下拉菜单项 |
| 下拉选择 | 2 | 下拉选择框 |
| 超链接 | 2 | 正文超链接 |

> 表单控件类（单行文本 / 下拉选择 / 日期 / 开关 / 附件）如出现，沿用同类写法。
> 遇到词表里没有的类型：**优先复用已有词**，确需新增时全文档统一，不要为同一控件造多个说法。

### 1.4 `规则/说明` 写法约定
- 全部以动作开头："点击…"、"勾选…"、"选择…"、"输入…"；
- 写清去向与结果："点击后进入对应项目的需提交待办详情页"；
- 有二次确认必须写明："弹出框询问用户是否删除"；
- 有权限约束要带出角色："项目负责人、项目创建人可对项目详情进行编辑"；
- 不写技术实现（接口名、表名、SQL）。

### 1.5 输入 / 输出表（七节式 `输入、输出` 节新增）

| 表头 | 用在哪 | 写什么 |
|---|---|---|
| `数据项 \| 来源 \| 说明` | `输入` | 这个功能点**运行需要**哪些数据、从哪来、怎么取 |
| `数据项 \| 去向 \| 说明` | `输出` | 这个功能点**产生或改变**哪些数据、写到哪去、什么后果 |

**`来源` / `去向` 列的标准用词**（同一份文档内统一，不要为同一来源造多种说法）：

| 用词 | 什么时候用 |
|---|---|
| `人工录入` | 页面上由人填写 / 勾选的 |
| `<系统名>对接` | 从别的系统同步来的（`投行项目管理系统对接`、`底稿系统推导`、`财务系统对接`） |
| `系统推导` | 由系统按已有数据和规则算出来的（非人工、非对接） |
| `参数配置` | 来自基础维护 / 配置菜单里配好的参数 |
| `导入文件` | 通过 Excel / 模板批量导入的 |
| `去向：<页面/模块>` | 写到本系统某个页面 / 模块（`去向：底稿详情页`） |
| `去向：<外部系统>` | 推送给别的系统（`去向：投行项目管理系统`） |
| `去向：文件导出` | 生成 Excel / PDF 等文件给用户下载 |
| `去向：系统日志` | 只落留痕，不产生业务数据 |

> **两张表都由脚本自动补表头**，只写数据行即可。数据项很少时可退化成项目符号，但**来源/去向必须写清**。
> 口径要点：来源/去向**不写技术实现**（接口名、表名、SQL、中间表名），只写到"哪个系统 / 哪个页面 / 哪份文件"这一层。

## 四、【菜单目录】表

`一级菜单 | 二级菜单 | 三级菜单`（52 行），同级重复留空。命名后缀约定：
- `（开源）` —— 客户定制菜单，标准产品没有；
- `以开源非信创版本菜单为准` —— 沿用客户既有版本菜单，不重新设计。

## 五、定制化需求专用表

> **只有项目确有定制内容时才会用到**。没有定制内容就**整章不写**（连引言、需求总览一起省），
> 别留空标题 —— 空标题还会白占一个自动编号。

| 表头 | 用途 |
|---|---|
| `条目 \| 需求名称 \| 新系统主要落点` | 需求总览（条目编号 `1.0`、`2.0`…） |
| `字段名称 \| 内容要求 \| 数据来源` | 对接字段清单（注意是"内容要求"不是"字段说明"） |

## 六、常用句式库

### 使用角色
- 逐条写角色名（**加项目符号**）：`项目业务人员` / `综合管理部人员` / `部门负责人` / `质控人员`
- 只有一条时写成一行（不加圆点）；**不要写成"使用人员：xxx"** —— 那是旧四段式的写法

### 权限（**三要素**，不写"使用人员"）
- `菜单权限：<角色>拥有该菜单权限。`
- `菜单权限：登录用户均有首页权限`
- `菜单权限：不涉及` / `功能权限：不涉及`
- `列表数据权限：<角色>可查看<数据范围>`
- `维护－包括：新建、下载样本、导入项目、查询、项目详情。`
- `查看－包括：查询、项目详情。`
- `编辑－项目负责人、项目创建人`

### 业务规则
- 逐条写"什么条件下必须/不能怎样"；无则写 `无`
- 原「补充说明」的边界情况 / 限制条件 / 后续规划也写在这里
- 状态枚举用表：`状态类型 | 状态说明`

### 功能说明
- `功能概述`：叙述段落（首行缩进），如 `首页以待办卡片形式汇总当前用户的底稿任务。`
- `配置菜单：<一级>－<二级>－<三级>`
- `二级页面：`
- `操作说明：`
- `界面原型图：`
- `新增“<筛选项>”筛选项，<哪几个列表>都增加。`

### 页面字段说明
- `不涉及`
- 表：`字段名称 | 规则/说明`（原「字段说明」+「字段逻辑」合并）

### 输入、输出
- `输入：` + 表 `数据项 | 来源 | 说明`
- `输出：` + 表 `数据项 | 去向 | 说明`
- 来源用词：`人工录入` / `<系统名>对接` / `系统推导` / `参数配置` / `导入文件`
- 去向用词：`去向：<页面/模块>` / `去向：<外部系统>` / `去向：文件导出` / `去向：系统日志`

### 对接类（H2 系统对接需求）
- `模块：<模块名>`
- `需求说明：`
- `参考<系统>提供的接口文档，实现<A>向<B>同步<数据>。`
- `客户提供数据中心的连接方式、数据库表及原来的同步视图脚本。`

### 定制需求出处标注
- `定制需求梳理清单原始条目（第 4 部分）`

### 备注/批注
- 用 `annotation text` 样式（styleId 12），例如：`已经报送的就不要再次提醒。`
- 编写说明允许"蓝色斜体字作为注释或举例"。

## 七、写作口径

- 人称：业务视角，主语是"系统"或角色名，不出现"我们/我认为"。
- 时态：陈述现状用"目前…"，写需求用"支持…/可…/需…"。
- 单位：日期用 `YYYY-MM-DD` 或 `xxxx年xx月xx日`，与人名/条目保持一致即可。
- 禁止：写实现方案（表名、接口名、代码类名）、写工作量、写排期——这些属需求变更单/工作量评估表，不在需求规格说明书内。

## 八、逐条列的排版：一律用项目符号

**逐条并列的内容（不是段落式的叙述）统一加项目符号**，排版细节见 `03-样式与编号规范.md` 第十节。

| 位置 | 是否加圆点 | 说明 |
|---|---|---|
| `业务说明` | **不加** | 叙述性段落（首行缩进 2 字符）；加了圆点就变成清单，不像"说明" |
| `功能说明` 的 `功能概述` | **不加** | 同上，叙述性段落（首行缩进 2 字符） |
| `业务规则` 各条 | 加 | 判定 / 流转 / 状态 / 限制 / 边界 |
| `使用角色` 各条 | 加 | 角色名清单 |
| `权限说明` 各条 | 加 | 菜单权限 / 功能权限 / 列表数据权限（**没有"使用人员"**） |
| `页面字段说明` 多条目 | 加 | 表格形态不加（表格自带框线，不需要圆点） |
| `输入、输出` 的条目（退化写法） | 加 | 表形态不加 |
| 段落级清单（"本章节暂未收录的需求"等） | 加 | 用 `('bullets', [...])` 块 |
| 只有一条的内容（"无""不涉及"） | **不加** | 「● 无」很怪，直接写一句话 |

**还有一条七节式专有的口径：节标题已经承担了标签职责时，不要再写一遍标签行。**

| 节 | 要不要写 `xxx：` 标签行 | 为什么 |
|---|---|---|
| `业务规则` / `使用角色` / `页面字段说明` | **不写** | 这三个节名本身就是 H5 标题，正文再来一行"业务规则："是重复 |
| `功能说明` 里的 `二级页面` / `操作说明` | **写** | 它们是**节内子要素**，没有自己的标题 |
| `输入、输出` 里的 `输入` / `输出` | **写** | 一节含**两段**，必须靠标签区分 |

> 脚本已按此实现：`req()` 里这三个节走 `_labelled(..., prefix=False)`，调用方不用管。

两条配套口径：

1. **条目里原来的手写序号（`1、2、3、`）要去掉** —— 与圆点叠起来是两层标记（"● 1、…"）。
   若某条序号**被正文引用**（"见第 4 点"），那一条改用普通段落，不加圆点。
2. **项目符号用 numbering 定义，不要手打"●"** —— 手打的圆点没有悬挂缩进，长条目换行后会顶到圆点下面。
