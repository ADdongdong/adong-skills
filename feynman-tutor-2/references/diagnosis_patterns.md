# 根因诊断与补强模式库

## 评估反馈决策树（核心，可机器执行）

每次评估必须输出结构化结果，使宿主能机器解析并执行分支。

```
用户输入作业答案
  → 内核评估答案质量（是否展现真实理解，而非复述）
      ├─ 通过？
      │     → PASS：标记该概念掌握 → PRACTICE（条件触发）→ MODULE_DONE
      └─ 不通过？
            → 诊断根因（DIAGNOSE）：
                ├─ 概念混淆
                │     → 换一个完全不同领域的类比重讲 + 变式题（同概念不同场景）
                │     → 再次 ASSESS
                ├─ 缺前置知识
                │     → 插入前置微课（暂停当前模块）
                │     → 前置小测通过 → 回到当前概念 ASSESS
                ├─ 表达问题（理解但说不清）
                │     → 换题型递进：选择 → 填空 → 用自己的话，逐级提升
                │     → 再次 ASSESS
                ├─ 学习超 40 分钟 / 状态差
                │     → 主动建议休息，记录精确进度
                │     → 结束会话（下次从此处继续）
                └─ 以上都试过仍不行
                      → 建议降低目标等级，调整学习计划（需用户确认）
```

## 评估标准（内核判断"通过"的依据）

- 用户能用**自己的话**解释概念本质（不是背诵定义）
- 能说明**为什么这样**（机制/因果），而不只是**是什么**
- 能举出一个**生活化或跨领域**的例子
- 面对一个**变式问题**能正确推理（不只是记住原题答案）
- 满足以上 3/4 即视为通过；仅"复述正确但说不清为什么"判为「表达问题」

## 根因诊断表

| 根因 | 触发信号 | 补强动作 | 验证手段 |
|---|---|---|---|
| **概念混淆** | 把 A 概念当成 B；类比用错；两概念边界模糊 | 换一个**完全不同领域**的类比重讲；指出混淆点 | 变式题（同概念不同场景） |
| **缺前置知识** | 卡在一个更基础的概念上；术语不懂；推导断裂 | 插入前置微课（暂停当前模块），只讲前置 | 前置小测（1 题即可） |
| **表达问题** | 回答正确但语言混乱；能选对但不会写；"我懂但说不出来" | 换题型递进：选择 → 填空 → 用自己的话 | 逐级递进，最后仍要"用自己的话" |
| **超 40 分钟** | 会话时长 > 40min，或用户显疲态 | 主动建议休息，记录精确进度（当前概念/步骤） | 下次从此处继续，不重头来 |
| **全无效** | 上述都试过仍不通过 | 建议降低目标等级（🟢能看懂/🟡能用上/🔴能设计），重规划 | 用户确认后生效 |

## 通用补强话术骨架

### 概念混淆
「你刚才把 X 和 Y 混在一起了——它们关键区别在于……我们换个比方：……」

### 缺前置知识
「在讲这个之前，得先搞懂一个更基础的东西：……（微课）懂了的话，先答这一个小问题：……」

### 表达问题
「你其实懂，只是没组织好。先选一下哪个对？→ 再填个空 → 最后用一句话总结。」

### 超 40 分钟
「你已经学了快一小时了，效率会下降。我们先停在这里（你已掌握到：……），下次接着来。」

### 全无效
「这个方向对你暂时有点陡。我们可以把目标从『🔴能设计』调到『🟡能用上』，压力小一点，先把主干搞懂。要调整吗？」

## 状态迁移规则补充

- `LECTURE` 收到「没太懂」→ 就地补讲（不离开 LECTURE，按预设理由精准补）
- `ASSESS` 收到用户答案 → **先输出反馈（哪些对/哪些有问题）** → 再输出评估结果 → PASS 则 `PRACTICE`（条件触发）→ `MODULE_DONE`；FAIL 则 `DIAGNOSE`
- `ASSESS` 失败 → `DIAGNOSE` → `REMEDIATE` → 回到 `HOMEWORK`（同一概念换变式题）或 `LECTURE`（需重讲）
- 学习超 40 分钟 → `REMEDIATE(休息)` → 记录精确进度 → 结束会话（宿主保存断点）
