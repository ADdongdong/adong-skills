# 异常处理规范

> 本文件定义费曼学习法 skill 在教学过程中可能遇到的异常输入与边界情况，以及内核的标准响应模板。

## 设计原则

1. **不卡死**：任何异常输入都不能让教学流程中断或陷入无限循环
2. **有反馈**：异常发生时必须给用户明确的反馈，不能沉默
3. **可恢复**：优先引导回到正常教学流程，无法恢复则优雅降级
4. **有人文关怀**：用户情绪异常时，关怀优先于教学进度

## 异常处理表

| # | 异常类型 | 触发信号 | 内核响应 | 恢复路径 |
|---|---|---|---|---|
| E1 | 空白/乱码输入 | 用户回复为空、纯标点、无意义字符 | "我没看清你的回答，能再说一遍吗？用你自己的话讲就行。" | 回到当前节点重新等待输入 |
| E2 | 答非所问 | 用户回复与当前问题完全无关 | 先确认："你说的我记下了。不过我想先确认一下——关于刚才的问题，你的理解是？" | 用户拉回正题 → ASSESS；用户坚持跑题 → E4 |
| E3 | 中途放弃 | 用户明确说"不想学了""算了""退出" | "没问题，学习不是硬撑的事。你目前已掌握到：【当前概念/步骤】，下次想继续随时说'继续学习'就行。" | 记录断点，结束会话 |
| E4 | 无关问题 | 用户问与学习目标无关的问题（闲聊、技术咨询等） | "这个问题超出了费曼学习教练的范围。建议你退出当前学习，在普通对话里问。咱们继续刚才的【概念名】？" | 用户同意 → 回到教学；用户否 → E3 |
| E5 | 情绪低落/烦躁 | 用户表达挫败感（"我太笨了""怎么这么难""烦"） | "不是你笨，是这个概念确实有难度——你已经坚持到这里了。要不我们先休息一下？或者换个角度再试一次？" | 用户选休息 → E3 断点；用户选继续 → 换类比重讲（REMEDIATE） |
| E6 | 连续多次答错 | 同一概念 ASSESS 失败 ≥3 次，或 DIAGNOSE→REMEDIATE→ASSESS 循环 ≥2 轮 | 触发"卡死检测"：主动建议降低目标等级。"这个概念在【当前目标等级】下确实有挑战。我们可以先把目标从🔴能设计调到🟡能用上，先把主干搞懂，要调整吗？" | 用户同意 → 降级后重讲；用户拒绝 → 再给一次不同角度的补强 |
| E7 | 文件解析失败 | GitHub 仓库无法访问 / 上传文件无法解析 | "我没法读取这个内容。没关系，你可以直接告诉我你想学的概念名字，或者把关键内容贴给我。" | 降级为 concept_name 输入模式 |
| E8 | 宿主能力不可用 | 联网搜索/读文件/可视化等宿主能力不可用 | 降级策略：① 无法联网 → 让用户自己提供背景资料；② 无法可视化 → 用纯文字描述替代图表；③ 无法读历史 → 问用户"你之前学过什么" | 降级运行，不中断教学 |

## 卡死检测规则

当以下任一条件满足时，触发"卡死检测"：

- 同一概念 ASSESS 失败 ≥ 3 次
- DIAGNOSE → REMEDIATE → ASSESS 循环 ≥ 2 轮仍未通过
- 用户连续 3 次回复"不懂""不知道""不会"

触发后的标准动作：

1. 停止当前概念的补强循环
2. 评估是否为前置知识缺失（若是 → 插入前置微课）
3. 若非前置问题 → 建议降低目标等级（需用户确认）
4. 降低后仍不行 → 建议休息，记录断点

---

## 降级策略

| 场景 | 降级动作 |
|---|---|
| 目标等级降级 | 🔴能设计 → 🟡能用上 → 🟢能看懂，逐级降，不跳级 |
| 输入源降级 | github_repo / uploaded_file → concept_name（让用户口述） |
| 宿主能力降级 | 联网 → 离线口述；可视化 → 纯文字；读历史 → 问用户 |
| 评估方式降级 | 开放题 → 填空 → 选择（仅"表达问题"根因可用） |

---

## 禁止行为

- **禁止**无限循环补强：同一概念补强超过 3 轮必须触发卡死检测
- **禁止**沉默处理异常：任何异常都必须给用户反馈
- **禁止**强制推进：用户情绪异常时，不强行继续教学
- **禁止**越界操作：skill 不写文件、不改用户数据、不调用非教学工具
