## 构思方法（Ideation）

### 多视角构思
- PM 视角：商业价值和市场机会
- 设计师视角：用户体验和情感需求
- 工程师视角：技术可行性和创新空间
- 针对现有产品：优化和改进切入
- 针对全新产品：从 0 到 1 创意

---

## 假设识别

### 现有产品（4 种风险）
1. **价值风险**: 用户会用它吗？
2. **可用性风险**: 用户能用吗？
3. **可行性风险**: 我们能做吗？
4. **生存能力风险**: 能持续运营吗？

### 全新产品（8 种风险）
以上 + 道德风险、GTM 风险、战略对齐风险、团队风险

### 假设优先级
使用 Impact × Risk 矩阵：
- 高影响 + 高风险：优先验证
- 低影响 + 低风险：可延迟

## 实验设计

### 快速验证实验（现有产品）
- A/B 测试
- 假门测试（Fake Door Test）
- 原型测试
- 可用性测试

### 精益创业预演（全新产品）
- XYZ+S 假设: X% of Y will Z if we S
- 落地页测试（Landing Page Test）
- 预购测试（Pre-order Test）— 测试付费意愿
- YODA 原则: 用你自己的数据（Your Own Data），不依赖第三方报告

## 机会评估

### 机会解决方案树（Teresa Torres）
```
期望结果（Outcome）
├── 机会 1（用户未被满足的需求）
│   ├── 解决方案 A
│   ├── 解决方案 B
│   └── 实验 → 验证
├── 机会 2
└── 机会 3
```

### 机会评分
```
Opportunity Score = Importance × (1 - Satisfaction)
```
- Importance: 用户觉得这个有多重要？（1-5）
- Satisfaction: 用户对现有方案的满意度？（1-5）
- 高分 = 重要但满意度低 = 好机会

## 功能优先级排序

### ICE 快速排序
```
ICE Score = Impact × Confidence × Ease
```

### RICE 详细排序
```
RICE Score = (Reach × Impact × Confidence) / Effort
```

### 功能请求分析
- 主题聚类：将相似请求分组
- 战略对齐评估：是否匹配产品方向？
- 用户影响面：影响多少用户？

## 用户研究

### 用户访谈脚本
- 遵循《妈妈测试》原则
- 询问 JTBD 探索性问题
- 聚焦过去的具体行为（不是未来假设）
- 不做推销，多听

### 访谈总结
- 结构化模板：JTBD、满意度信号、行动项
- 区分观察数据和主观判断

### 指标仪表盘
- 北极星指标 + 输入指标
- 健康指标 + 告警阈值
- 反指标（防止古德哈特定律）
