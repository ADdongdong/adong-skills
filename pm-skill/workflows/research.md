# 产品研究工作流

## 概述

执行结构化的产品研究——市场、竞品、用户、技术趋势——生成有据可查的研究报告。

## 前置条件

- 用户提供了研究主题
- 明确研究范围（深度、广度、格式）

## 执行步骤

### 步骤 0：定义研究问题

与用户确认研究范围：

1. **研究什么？**
   - 竞品分析：识别和深度分析竞品
   - 市场研究：TAM/SAM/SOM 估算
   - 用户研究：用户画像、痛点、行为模式
   - 技术趋势：行业技术方向、新兴技术应用

2. **多深？**
   - 快速扫描（30 分钟级）：3-5 个主要发现
   - 标准研究（1-2 小时级）：结构化报告
   - 深度研究（3+ 小时级）：多来源交叉验证

3. **什么格式？**
   - 结构化报告（默认，使用 RESEARCH.md 模板）
   - 简要汇报
   - 演讲/幻灯片提纲

### 步骤 1：信息收集

**1.1 检测研究引擎**：

```
# 检测 deerflow-skill
ls ~/.claude/skills/deerflow/ 2>/dev/null && echo "deerflow: ✅" || echo "deerflow: ❌ 未安装"

# 检测 llm-wiki-skill
ls .wiki/ 2>/dev/null && echo "wiki: ✅" || echo "wiki: ❌ 未安装"
```

根据可用引擎选择策略：
- deerflow ✅ → 首选 deerflow --ultra 做深度调研
- deerflow ❌ → 降级为 Agent 原生 WebSearch

**1.2 Web 研究（deerflow-skill — 首选）**：

根据研究深度选择 deerflow 模式：

| 深度 | 命令 | 示例 |
|------|------|------|
| 快速查询 | `/deer --flash` | "/deer --flash Tesla 2025 Q4 revenue" |
| 标准调研 | `/deer` | "/deer 调研 RAG 技术的最新进展" |
| 结构化分析 | `/deer --pro` | "/deer --pro 对比分析 Notion 和 Confluence 的功能差异" |
| 全面深度调研 | `/deer --ultra` | "/deer --ultra 深度调研 AI 代码审查工具的竞品格局：识别 Top 5 竞品，每家从功能、定价、GTM、用户评价四个维度分析" |

`--ultra` 模式下，deerflow 自动将任务拆解为并行子代理：
- 子代理 1：调研竞品 A
- 子代理 2：调研竞品 B
- 子代理 3：调研竞品 C
- ...（并行执行，大幅缩短调研时间）

**1.3 Web 搜索（Agent 原生 — 降级方案）**：
- 使用 WebSearch 进行多轮搜索
- 竞品搜索：`"{product} competitors"` `"{行业} 市场规模"`
- 用户研究：`"{目标用户} 痛点"` `"{行业} 用户调研"`
- 使用 WebFetch 读取关键来源的完整内容

**1.4 Wiki 搜索**（如有 llm-wiki-skill）：
- 搜索已有知识库中的相关实体和概念
- 识别知识空白 → 优先用 deerflow 补充

### 步骤 2：分析综合

**竞品分析框架**：
| 维度 | 竞品 A | 竞品 B | 竞品 C | 本产品定位 |
|------|--------|--------|--------|------------|
| 目标用户 | | | | |
| 核心功能 | | | | |
| 定价模式 | | | | |
| GTM 渠道 | | | | |
| 优势 | | | | |
| 劣势 | | | | |
| 差异化机会 | | | | |

**市场分析框架**：
- TAM（总可寻址市场）
- SAM（可服务市场）
- SOM（可获得市场）
- 增长率
- 关键趋势

**用户分析框架**：
- 用户画像（JTBD、痛点、收益）
- 用户旅程（认知 → 考虑 → 购买 → 使用 → 推荐）
- 行为模式

### 步骤 3：生成报告

遵循 `templates/RESEARCH.md` 模板：

1. **执行摘要**（1-3 段）
2. **研究问题**（我们想了解什么）
3. **方法论**（怎么研究的）
4. **主要发现**（数据驱动的结论）
5. **竞品/市场/用户详细分析**
6. **关键洞察**（超越数据的理解）
7. **建议**（可执行的行动项）
8. **来源**（所有引用的 URL 和文件）

### 步骤 4：知识结晶（可选）

如有 llm-wiki-skill：
- 将关键发现写入 wiki（实体、概念）
- 将竞品信息结晶为实体页面
- 将市场数据结晶为概念页面

## 关键规则

- 所有数据标注来源（URL 或文件引用）
- 区分**数据**（可验证）和**洞察**（推断）
- 不要只列数据——给出"这意味着什么"
- 中文输出
