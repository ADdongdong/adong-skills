# 发布 & GTM 工作流

## 概述

为产品发布制定完整的发布说明和 Go-to-Market 计划。

## 前置条件

- 产品策略已定义（有 STRATEGY.md 或策略阶段完成）
- PRD 已冻结（对发布范围有清晰认知）

## 执行步骤

### 步骤 1：发布范围确认

1. 理解发布内容：
   - 新产品发布 vs. 功能发布 vs. 版本更新
   - 核心功能列表
   - Breaking changes（如有）
   - 目标用户群体

2. 确认发布级别：
   - 🚀 Major Launch（新产品/新市场）
   - 📦 Feature Release（重要功能）
   - 🔧 Minor Update（修复和优化）

### 步骤 2：发布说明生成

创建 `RELEASE.md`（遵循 `templates/RELEASE.md`）：

1. **版本信息**：版本号、发布日期、代号
2. **功能列表**：用户视角的 What's New
3. **Breaking Changes**：必须告知用户的变更
4. **升级指南**：用户怎么获取新版本
5. **已知限制**：透明化已知问题

**规则**：
- 从用户视角写，非技术视角
- 用通俗语言（小学毕业水平可理解）
- 每条功能 = 用户收益 + 使用方式

### 步骤 4：ICP 定义

**理想客户画像**：
- 人口统计/企业特征
- JTBD（待完成的任务）
- 当前痛点
- 购买行为
- **取消资格标准**（谁不是目标客户）

### 步骤 5：消息 & 价值主张

```
一句话价值主张:
"对于 {target user}，{product name} 是 {product category}，
它 {key benefit}。不像 {competitor alternative}，
我们的产品 {unique differentiator}。"
```

为不同受众定制消息：
- 最终用户的消息
- 决策者/采购者的消息
- 合作伙伴/渠道的消息

## 关键规则

- 所有消息从用户视角出发
- 发布说明用通俗语言
- 记录假设（特别是市场反应假设）
- 中文输出
