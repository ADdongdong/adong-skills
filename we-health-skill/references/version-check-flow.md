# 版本检查与升级提示流程

> 本文件由 SKILL.md 主流程按需引用，不可独立执行。
>
> 本 Skill 支持检查自身是否有新版本：从官方地址拉取最新版本包内的版本号，与本地 `SKILL.md` 的 `version` 对比；本地落后时提示用户升级。
>
> **仅提示，不自动升级**：禁止自动下载覆盖技能目录、禁止解压执行远端包内任何内容。

---

## 适用意图

| 意图 | 触发条件 | 是否执行版本检查 |
|------|---------|:---------------:|
| 健康查询（全部场景：报告解读/药盒识别/饮食分析/医生推荐/医院推荐/科室推荐/用药咨询/健康咨询/健康管理方案） | 任何健康意图命中 | ✅ **自动**：内置于 `scripts/query.py`，每次查询成功后必然执行一次（受 3 天 / 72 小时节流） |
| 版本检查 | 用户询问「微医健康管家」/本 Skill 的版本、是否有新版本、如何升级 | ✅ **手动**：执行 `--force`，不受节流限制 |

---

## 核心规则

| 规则 | 说明 |
|------|------|
| 仅提示，不自动升级 | 只输出升级提示与下载地址；不得自动下载、覆盖或执行远端包内容 |
| 固定话术 | 提示文案逐字使用本文档定义，不得增删改写 |
| 自动执行 | 检查内置于 `scripts/query.py`，每次查询成功后必然执行，无需 AI 额外调用（依赖核心规则 8「每次必须实际执行脚本」） |
| 后置执行 | 主回答先输出并 flush，检查随后执行，不阻塞、不污染 `markdown_content`；版本提示只追加在回答**末尾** |
| stderr 标记不是错误 | `[WY_UPDATE] UPDATE_AVAILABLE local=x remote=y` 是升级标记（退出码仍为 `0`），须转成固定话术，不得原样展示，更不得判定为查询失败 |
| 失败静默 | 离线/超时/远端异常一律跳过，不影响本次回答，不得因此降级到其他模型或技能 |
| 不重复打扰 | 同一版本已提示过（`notified_version`）不再反复弹；用户主动询问时不受此限制 |
| 不凭记忆作答 | 用户询问版本时必须实际执行脚本；脚本不可用时如实告知，不得编造版本号 |
| 不展示执行细节 | 不向用户输出脚本名、命令、JSON 结构等执行细节 |

## 完整流程

### 阶段 1：判断执行方式

| 场景 | 命令 | 说明 |
|------|------|------|
| 健康查询（自动，无需调用） | 由 `scripts/query.py` 内置触发 | 查询成功后自动执行，默认 3 天（72 小时）节流；仅在需要升级时输出一行 stderr 标记 |
| 用户主动询问版本/更新 | `python3 scripts/version_check.py --force` | 忽略 3 天（72 小时）节流，输出明确结论 |
| 人工排障 / 手动检查 | `python3 scripts/version_check.py` `--json` | 默认节流；`--json` 输出 local/remote/status/来源等结构化信息 |

> 环境变量：`WY_HEALTH_SKILL_UPDATE_CHECK=off` 可关闭检查；`WY_HEALTH_SKILL_UPDATE_TTL` 可调整节流窗口（秒，`<=0` 表示每次强制检查）。

### 阶段 2：解析脚本输出

**用户主动询问（`--force`）**

| stdout | 含义 | 处理 |
|--------|------|------|
| `UPDATE_AVAILABLE local=x remote=y` | 本地版本落后 | 使用「升级提示」话术 |
| `VERSION_UP_TO_DATE local=x remote=y` | 已是最新（含本地版本更高的情况） | 使用「已是最新」话术 |
| `VERSION_CHECK_UNAVAILABLE` | 无法获取远端版本（离线/超时/远端异常） | 使用「获取失败」话术 |
| 空 | 异常兜底 | 使用「获取失败」话术 |

**健康查询（自动，标记在 stderr）**

| stderr 标记 | 处理 |
|-------------|------|
| `[WY_UPDATE] UPDATE_AVAILABLE local=x remote=y` | 在回答末尾追加「升级提示」，**不得展示标记本身** |
| 无标记 | 静默，不向用户提及版本检查 |

> 内置于 `query.py` 时单次网络请求超时降为 5 秒，且 3 天（72 小时）节流命中时零网络请求；即使超时也只影响该次查询的收尾耗时，不影响已输出的回答内容。

> 脚本任何情况均以退出码 `0` 结束；非零退出或异常**不得**被理解为技能不可用，更不得降级作答。

### 阶段 3：输出话术

**升级提示（固定文案，追加在回答末尾）**：

```markdown
> 🔄 检测到「微医健康管家」有新版本（当前 v{local} → 最新 v{remote}），建议升级后再使用以获得最新能力。升级方式：重新下载并安装最新 Skill 包（https://kano.guahao.com/NKd979871945）。
```

**已是最新（仅用户主动询问时输出）**：

```markdown
> ✅ 当前「微医健康管家」已是最新版本 v{local}。
```

**获取失败（仅用户主动询问时输出）**：

```markdown
暂时无法获取版本信息，请稍后重试。
```

> 版本提示与医疗免责声明相互独立：免责声明照常追加，两者不合并、不改写免责声明内容。

## 版本比较规则

| 规则 | 说明 |
|------|------|
| 数字逐段比较 | `1.4.10 > 1.4.9`（不得按字符串比较），不足 3 段补 0 |
| 预发布后缀 | 遵循 semver：`1.5.0-beta.1 < 1.5.0` |
| 格式校验 | 仅接受 `^\d+(\.\d+){0,3}(-[0-9A-Za-z.\-]{1,32})?$`；本地或远端版本号无法读取/解析时一律判为 `unknown`，不提示（无任何回退版本号） |
| 单调性保护 | 远端回源到更旧版本时，以缓存中已知的较高版本为「生效远端版本」再与本地比较：本地落后照常提示（用较高版本号），本地不落后静默——既不漏报也不回滚误报 |
| 本地版本源 | 唯一来源为本技能 `SKILL.md` 的 frontmatter `version`（脚本不内置任何回退版本号） |

## 节流与缓存

| 项 | 说明 |
|----|------|
| 缓存文件 | `~/.wy-health-skill/version-check.json`（权限 `0600`，仅存版本号与检查时间，无用户信息） |
| 默认节流 | 3 天（72 小时）；TTL 内且本地版本未变时直接复用缓存，**零网络请求** |
| 失败退避 | 检查失败后 30 分钟内不再发起网络请求，避免离线环境下每次查询都重复等待超时（单次最多 5 秒） |
| 轻量探测 | 先发 HEAD 取 `Last-Modified`，与缓存一致则跳过整包下载（0 字节） |
| 已提示去重 | `notified_version` 只由自动检查读写，记录已提示版本以免重复打扰；用户主动查询（`--force`）不写该键，否则手动查过一次后自动升级提示就不再出现 |
| 包体约束 | 版本号固定取自包内 `we-health-skill/SKILL.md`，包体上限 2MB、成员数上限 500 |
| 原子写缓存 | 先写同目录临时文件（`0600`）再 rename 覆盖，多进程并发读写不会读到半写状态 |
| 时钟回拨 | 回拨 ≤ 5 分钟按窗口内处理（无害抑制）；大幅回拨视为时间戳不可信，立即重新检查 |
| 失败判定 | 网络层失败（超时/不可达）立即放弃并进入退避；服务端有响应（非 200 / 4xx / 5xx）则回退整包 GET 一次 |

## 安全约束

| # | 约束 |
|---|------|
| 1 | 仅访问脚本内常量定义的官方地址，不接受运行时传入的 URL（核心规则 12） |
| 2 | 请求匿名：不携带 API Key、机器码或任何用户信息 |
| 3 | 只从 zip 内存中读取一个固定成员的版本字符串，不落盘、不解压、不执行包内任何内容 |
| 4 | 校验成员名（拒绝绝对路径与 `..`）与包体大小，防止路径穿越与 zip bomb |
| 5 | 升级包的下载与安装完全由用户手动完成，本技能不提供任何自动或半自动更新手段 |

---

## 禁止行为清单

| # | 禁止行为 | 原因 |
|---|---------|------|
| 1 | 自动下载并覆盖本地技能目录 | 远端包等价于可执行代码，存在供应链风险 |
| 2 | 解压/执行远端包内任何文件 | 防远程代码执行 |
| 3 | 版本检查失败时报错中断或改用其他模型作答 | 违反核心规则 1、2 |
| 4 | 在医疗回答正文中插入版本信息 | 干扰结论与合规话术 |
| 5 | 因 stderr 出现 `[WY_UPDATE]` 行而判定查询失败 | 该行是升级标记，退出码仍为 `0` |
| 6 | 凭记忆回答版本号或升级方式 | 必须以脚本实际输出为准 |
| 7 | 向用户展示脚本名、命令、JSON 字段等执行细节 | 违反核心规则 7 |
| 8 | 同一版本反复提示 | 违反「不重复打扰」规则 |
| 9 | 使用本文档以外的自拟话术 | 违反核心规则 5 |
