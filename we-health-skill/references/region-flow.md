# 地域敏感意图的地区确认流程

> 本文件由 SKILL.md 主流程按需引用，不可独立执行。
>
> 医生推荐、医院推荐、科室推荐、预约挂号等地域敏感意图在执行查询前需确认用户所在地区。

---

## 适用意图

> 对应 `SKILL.md` 意图识别中的分类。

| 意图 | 是否地域敏感 | 说明 |
|------|:----------:|------|
| 医生推荐（含在线问诊、预约挂号） | ✅ | 需按地区匹配附近医生，提供问诊和挂号 |
| 医院推荐 | ✅ | 需按地区推荐附近医院 |
| 科室推荐 | ✅ | 需按地区推荐附近医院科室及医疗服务 |
| 报告解读 | ❌ | 与地域无关 |
| 药盒识别 | ❌ | 与地域无关 |
| 用药咨询 | ❌ | 与地域无关 |
| 健康咨询 | ❌ | 与地域无关 |

---

## 核心规则

| 规则 | 说明 |
|------|------|
| 仅地域敏感意图触发 | 非地域敏感意图不询问地区，直接查询 |
| 最多询问 1 次 | 仅在地区缺失时询问 1 次，用户回答后立即查询 |
| 优先从上下文提取 | 先检查用户原话和对话上下文是否已包含地区信息 |
| 用户可拒绝提供 | 用户不愿提供地区时，不传 `region` 直接查询（降级） |

---

## 完整流程

### 阶段 1：地区信息检查

地域敏感意图触发后，AI 先检查是否已有用户地区信息，按优先级依次判断：

| 优先级 | 来源 | 示例 |
|--------|------|------|
| 1 | 用户当前 query 中明确提及地区 | "北京哪家医院看心血管好" / "帮我找个上海的眼科医生" |
| 2 | 对话上下文中用户曾提及地区 | 用户上一轮说"我在杭州"，本轮问"推荐个皮肤科医生" |

- **已有地区** → 提取地区，进入阶段 3
- **无法确定地区** → 进入阶段 2

### 阶段 2：询问用户地区（仅 1 次）

向用户询问所在地区，话术：

> 请问您在哪个城市？这样我可以为您推荐附近的医生/医院/科室。

等待用户回答后：

- **用户提供了地区** → 提取地区，进入阶段 3
- **用户明确表示不需要指定地区** / **不愿提供** → 不传 `region`，直接查询（降级）

> 注意：这是**唯一一轮**地区询问。用户回答后立即执行查询，不得反复追问。

### 阶段 3：执行查询（携带 region）

将获取到的地区通过 `region` 参数传入查询：

**CLI 模式**：

```bash
python3 scripts/query.py "经常头痛，帮我推荐个神经内科医生" --region 北京
```

**stdin JSON 模式**：

```bash
python3 scripts/query.py --stdin << 'EOF'
{
  "query": "经常头痛，帮我推荐个神经内科医生",
  "region": "北京"
}
EOF
```

如用户未提供地区（阶段 2 降级），则不传 `region`，仅传 `query`。

## 禁止行为清单

| # | 禁止行为 | 原因 |
|---|---------|------|
| 1 | 对非地域敏感意图询问地区 | 多余追问，影响体验 |
| 2 | 用户已提供地区后仍反复询问 | 违反「最多询问 1 次」规则 |
| 3 | 用户拒绝提供地区后拒绝服务 | 应降级为不传 region 直接查询 |
| 4 | 询问地区超过 1 轮 | 违反地区询问限制 |
| 5 | 将地区信息写入 query 而非 region 参数 | 地区应通过 `region` 参数传入 |
