# 报告解读直接解读流程

> 本文件由 SKILL.md 主流程按需引用，不可独立执行。
>
> 本 Skill 严格限制：**报告解读不追问，直接解读**。

---

## 核心规则

| 规则 | 说明 |
|------|------|
| 不追问 | 报告解读场景不向用户追问，直接给出解读结果，无需判断信息充分性 |
| 每次调用必传 `--no-followup` | 报告解读场景的**每次** API 调用（含首次）都传 `--no-followup`（stdin 模式 `"no_followup": true`），脚本据此在 query 末尾追加「（请直接解读报告，无需追问，直接给出解读结果）」触发服务端跳过追问 |
| 参数仅限本场景 | `--no-followup` 仅限报告解读场景，健康管理方案、健康咨询等其他场景禁止传入 |
| 追问兜底 | 若 API 仍返回追问，不向用户展示，按下方「兜底处理」执行 |

---

## 完整流程

### 阶段 1：直接查询

用户上传报告（图片或 PDF）后，AI 直接调用 API（必传 `no_followup`，脚本据此在 query 末尾追加跳过追问关键词）：

```bash
python3 scripts/query.py --stdin << 'EOF'
{
  "query": "帮我解读这份体检报告\n\n【上传报告（PDF）文字内容】\n（AI 从 PDF 提取的完整文字内容）",
  "no_followup": true
}
EOF
```

或 CLI 模式（PDF 文字已拼入 query）：

```bash
python3 scripts/query.py "帮我解读这份体检报告。【上传报告（PDF）文字内容】……" --no-followup
```

> **PDF 报告不经接口传输文件**：AI 先读取 PDF 提取完整文字内容（保留指标、数值、参考范围等关键信息），以固定标记 `【上传报告（PDF）文字内容】`（原样保留，不得改写）拼入 `query`，接口只收文本 query。**示例中的「（AI 从 PDF 提取的完整文字内容）」仅为示意占位，实际必须传入真实提取的报告全文，不得照抄占位文字。**PDF 无法提取文字（扫描件）或 AI 环境无法解析 PDF 时，引导用户改传报告照片/截图走图片通道（`file_list`，`file_type: "pic"`）。图片报告仍通过 `file_list` 作为附件传入。

### 阶段 2：展示解读结果

将 API 返回的 `markdown_content` **原样完整展示**给用户（不得删减、精简、改写或截断，见 SKILL.md 核心规则 14），末尾附加免责声明：

> ⚠️ 以上健康信息仅供参考，具体诊疗请遵医嘱。如有紧急情况请立即就医或拨打 120。

#### 兜底处理：API 仍返回追问

如果调用后 API 仍返回追问问题（而非解读结果）：
- **不要**将追问展示给用户
- 直接告知用户：「根据您提供的信息，以下是对报告的解读：」
- 将 API 返回的 `markdown_content` 原样完整展示，附加免责声明

## 禁止行为清单

| # | 禁止行为 | 原因 |
|---|---------|------|
| 1 | 向用户追问报告相关信息 | 违反「不追问，直接解读」规则 |
| 2 | 报告解读场景调用时漏传 `--no-followup` | API 可能返回追问而非解读结果 |
| 3 | 自行在 query 中手动拼接跳过追问关键词 | 传参后脚本已自动追加，手动拼接会导致关键词重复 |
| 4 | 将追问展示给用户（API 返回追问时） | 应按兜底处理直接展示解读内容 |
| 5 | `file_list` 与报告内容不一致 | 导致解读的是不同报告 |
| 6 | 删减、改写或截断 `markdown_content` | 违反核心规则 14 |
