# 教学范例

## 设计目的

记录完整教学案例，展示状态机各节点在真实对话中如何落地。每案例包含：完整流程追踪、关键教学决策注释、技巧提炼、陷阱题设计逻辑。

---

## 案例 1：数字水印（domain_knowledge → 偏 hard_skill）

**日期**：2026-07-25  
**概念**：数字水印（Digital Watermarking）  
**目标等级**：中间级（本学科阶梯 · 轻量版 PRACTICE）  
**结果**：ASSESS 通过 → PRACTICE 通过 → strong

---

### 完整流程追踪

```
节点 1（学科选择）
  输入：用户说"我要学习数字水印"
  动作：确认概念，无拆模块需求（单一概念即可覆盖）

节点 2（目标分级）
  动作：出示 3 张成果卡
  用户选择：中间级（本学科阶梯 · 轻量版 PRACTICE）
  决策：目标含「实际应用」，后续 ACTIVATE PRACTICE

前置知识检测
  探针题：数码照片在计算机里本质怎么存储？（A/B/C 选择）
  用户回答：B（像素网格 + 颜色值）— 且额外说出"计算机底层只认01"
  决策：前置掌握，直接进入 LECTURE

节点 4 — LECTURE（类比开场）
  类比：钞票防伪水印（人人见过、马上理解）
  覆盖 3 个核心属性：
    - 平时不注意（不可见性）
    - 想查就能查（可检测性）
    - 揉折洗不掉（鲁棒性）
  顺势引出 |可见水印| vs |不可见水印| 二分

节点 5 — HOMEWORK 1（开放推理题）
  题目：坏人裁边 + 压缩后，水印还能检出吗？为什么？
  设计意图：不考定义，考推理——正好引出下一个要讲的核心概念"鲁棒性"

节点 6 — ASSESS 1
  用户答：裁剪会丢部分点、压缩会导致像素数量不一 → 能检测出来
  反馈：✅ 方向对（会受损）/ ⚠️ 两点修正（压缩≠减少像素数、问题问的是水印是否可读而非是否被篡改）
  讲解：引出鲁棒性 → 冗余编码 → 低频嵌入 vs 高频细节
  锚点比喻："不把鸡蛋放一个篮子里"（RAID 磁盘类比）

节点 5 — HOMEWORK 2（变式题）
  题目：PDF 黑白文档嵌入员工工号做防泄密
  设计意图：换约束（无可用的高频细节）→ 验证用户能否迁移核心思路

节点 6 — ASSESS 2
  用户答：工号→01→每行像素±1→每行都有所以抗裁页→和原 PDF 做差
  反馈：✅ 三段全对（编码、冗余抗裁、非盲检测）/ ⚠️ 小补（PDF 是矢量轮廓，但逻辑正确）
  评估：通过（满足 4/4 标准）

节点 7 — PRACTICE（情境判断 × 3）
  场景 A（视频防泄密）：✅ 低频嵌入 + 冗余 = 正确
  场景 B（身份证归档，不可修改）：⚠️ 踩陷阱 — 水印是修改，该用哈希
  场景 C（云文档防截图）：✅ 逻辑对，补一刀：截图≠像素复制，工业界用可见浮水印
  难度：轻量版（中间级 · 判断+分析+说理由）
  自检：场景 B 只需"水印会修改原文件"这一已学知识，无额外前置 ✓

节点 8 — MODULE_DONE
  输出：before/after 对比 + 掌握清单（6 项概念逐一列出状态）
```

### 关键教学技巧提炼

#### 1. 锚定类比，全程复用

钞票水印在开场就建立了三个属性（不可见/可检测/鲁棒），后续讲鲁棒性、冗余编码、低频嵌入时不断回扣这个类比。用户脑子里始终有一个锚点，新知识挂上去就行。

> **模式**：开场类比不要只用一次就丢。选一个贯穿式比喻，每讲一个新子概念都回到它。

#### 2. 探针题选最小可验证点

像素存储方式是数字水印的唯一前置——不知道这个就没法理解"在数字里藏信息"。用一道选择题（而非问答题）7 秒搞定，不拖节奏。用户还自发做了拓展（"计算机只认 01"），说明前置不仅掌握，而且有深层理解。

> **模式**：探针题 = 1 个选择/填空 = 前置概念的最小必要面。通过就过，不过才插微课。

#### 3. HOMEWORK 题目本身就是"下一节课的引子"

第一道作业问"裁剪压缩后还能检出吗"，用户答完 → 正好引出鲁棒性。作业和下一段 LECTURE 无缝衔接，用户感觉不是"做题检验"，而是"我们一起在探索答案"。

> **模式**：设计作业题时，选一个用户凭现有知识能做出有洞察力推理、但会暴露知识缺口的方向。答案的"缺口"就是下一段讲解的入口。

#### 4. 陷阱题设计逻辑

PRACTICE 场景 B（身份证归档 + "不可有任何修改"）是刻意设的陷阱：

- 看起来像水印场景（需要防伪/验证）
- 实际上红线是"不可修改"，水印哪怕 ±1 也踩线
- 正解是哈希校验，不是水印

陷阱的价值不是"考倒用户"，而是让他**亲身体验"边界在哪儿"**。在实践中学到"水印是溯源工具，不是完整性校验工具"，比直接讲定义深刻十倍。

> **模式**：PRACTICE 至少设 1 个边界陷阱题——场景看起来适合水印，但仔细分析会发现红线在其他地方。这不是羞辱，是强化概念边界。

#### 5. 用户自主推导 = 最高效的内化

用户在没有学过 LSB（最低有效位嵌入）的情况下，自己推导出 "01编码 → 像素±1 → 每行都有 → 与原文件做差" 的完整方案。这比任何讲解都有效，因为是他自己的思维产物。

> **模式**：好的作业题应该让用户**自己重新发明**下一个要讲的概念。当他答出来的时候，你告诉他"你知道吗，你刚才推导的就是工业界用的 XXX"——那一刻的成就感无法替代。

### P7 反馈模式实录（供参考）

**ASSESS 1 反馈结构**：
```
✅ 你对水印受损的直觉是对的——裁剪和压缩确实会破坏部分水印信息，这个推理方向很准。
⚠️ 但有两个关键点需要修正：
   1. 压缩 ≠ 减少像素数……
   2. 你回答的其实是「能不能检测出图片被篡改过」，而我问的是……
```

**PRACTICE 反馈结构**：
```
✅ 场景 A：低频嵌入 + 冗余 = 全中。视频水印的核心策略你抓对了。
✅ 场景 C：逻辑对……需要补一刀：截图不是像素级复制……
⚠️ 场景 B：这是关键陷阱题，你踩中了。不可见水印哪怕只改 ±1，也是修改……
```

要点：每个 ✅ 都具体到**对在哪**，每个 ⚠️ 都解释**为什么差/偏差在哪**，不给空洞评价。

### 概念讲解层次

数字水印在这个案例中被拆为以下层次，由浅入深递进：

| 层级 | 概念 | 讲解方式 |
|---|---|---|
| L1 | 什么是数字水印 | 钞票水印类比 → 不可见/可检测/鲁棒三属性 |
| L2 | 怎么嵌入 | 像素±1 → 肉眼无感、机器可读 |
| L3 | 鲁棒性（核心） | 冗余编码 + 低频vs高频 → "不把鸡蛋放一个篮子" |
| L4 | 盲检测 vs 非盲检测 | 用户自己推导出"和原图做差"即非盲检测 |
| L5 | 实战边界 | 水印 vs 哈希、嵌入域选择、可见vs不可见的选择场景 |

这 5 层覆盖了从一个零基础用户到本案例目标（中间级 · 轻量版 PRACTICE）所需的全部知识。没有讲 DCT/DFT/扩频等进阶内容——那些属于本学科最高级（架构设计 / 推导建构）的范畴。

### 适用场景判断

本案例的讲述模式最适合以下类型的教学内容：

- **概念性强、有明确边界的单一概念**（不需要拆多模块）
- **有天然生活类比的概念**（钞票水印、快递分拣、族谱……）
- **有"看起来像但其实不是"的易混淆场景**（水印 vs 哈希、水印 vs 加密、水印 vs 隐写）
- **用户前置门槛低**（只需基础常识 + 最小编程/数学知识）

不适合的场景（需要其他模式）：

- 需要大量前置知识链的概念（如"理解 Transformer 需要先懂 attention → embedding → softmax……"）
- 纯操作型技能（如"怎么用 Excel 做数据透视表"）
- 价值观/态度类（如"什么是好的产品设计"）
