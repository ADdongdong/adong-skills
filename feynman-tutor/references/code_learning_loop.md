# 代码/源码学习闭环（Code Learning Loop）

> 归属：v1.1.7 | 配套：SKILL.md 节点 1/3/7/8
> 作用：当学习目标是一个**代码仓库**（GitHub 仓库 / 本地仓库路径 / 上传的代码文件）时，从"概念学习教练"升级为"既能学概念、也能学项目"——读源码定向 → 模块计划 → 概念级教学循环 → 模块级大作业 → 双轨归档 → 分支收尾。

---

## 1. 闭环总览

```
┌─ 入口：github_repo / uploaded_file / 本地仓库路径
│
├─ ① 读源码定向（节点1，github_repo 输入时新增）
│    架构图/README → 入口文件 → 模块划分 → 调用链/依赖图（P8 配图：模块依赖图）
│
├─ ② 模块计划（节点3，增强）
│    拆模块（沿用现有）+ 每个模块标注：是否配【模块级大作业】+ 类型（轻量/重量）
│
├─ ③ 概念级教学循环（节点4-7，保留不动）
│    LECTURE → HOMEWORK → ASSESS → PRACTICE（概念级，按相对位置）
│
├─ ④ 模块级大作业（新增，仅标注过的模块）
│    在 feynman/lab-<模块> 分支上做动手实验（预测→改动→验证→结论）
│
├─ ⑤ 归档（节点8，增强）
│    Obsidian：概念总结 + 作业记录子块
│    分支 NOTES.md：项目上下文内的实验细节（diff/环境）
│
└─ ⑥ 分支收尾
    全部模块学完 → 回 main → 问用户：lab 分支保留存档 / 合并 / 删除
```

---

## 2. 场景四态判定（决定实验自由度）

### 2.1 判据：影响范围（核心，一句话确认）

进入任何动手实验前，**必须**用一句话确认影响范围（沿用节点 1.5"推断可一票否决"范式）：

> 「这个仓库改动后**只影响你自己**（学习副本 / 你自己的学习 repo，随便玩），还是**会影响别人**（团队/共享/生产）？」

### 2.2 四态表

| 场景 | 判定特征 | 实验自由度 | push/merge 约束 |
|---|---|---|---|
| **学习副本** | clone 下来纯学习，本地分支，不 push | 重量实验自由（加功能/重构/删改） | 绝不 push/merge 到上游/他人仓库；本地分支 commit 留痕 |
| **自建学习 repo** | clone 上游 + 自己 GitHub 建学习 repo | 重量实验自由 | 绝不 push/merge 到上游；**可 push/merge 到自己的私有学习 repo**（用户确认后） |
| **工作区项目** | 正在开发、会推回团队/生产 | 轻量干预（加 log/注释调用/改配置/加断言） | 强制分支，改动经用户确认 |
| **临时片段** | 非 git 仓库 / 粘贴代码 / 现场示例 | 重量实验自由 | 无需分支，改坏重来 |

### 2.3 信号表（agent 预判依据，不替代确认）

| 信号 | 指向学习态 | 指向工作区 |
|---|---|---|
| 用户措辞 | "clone 下来学/研究/读源码" | "我的项目/我们组的项目/帮我在项目里加个…" |
| git remote | 有 origin 但近期未 push（学习 repo 例外：自己的 repo） | 有 origin 且近期 push 回团队 |
| 本地领先远程 | 无 / 只有学习 commit | 常有未推送的团队 commit |
| 分支状态 | 干净或仅学习分支 | feature 分支 + dirty 工作树 |
| 目录位置 | 学习/临时目录 | 日常开发目录 |
| 配置内容 | 默认/示例配置 | 生产配置（DB、密钥、部署脚本） |

**默认策略**：信号不足 → 按最保守（工作区）处理，用确认问题兜底。

### 2.4 临时片段快速判定
非 git 仓库（无 `.git`）/ 粘贴代码 / agent 现场示例 → 直接归入临时片段，无需确认。

## 3. 分支机制（按模块自动建/切）

### 3.1 粒度与命名
- **粒度 = 模块**：复用节点 3 的模块计划，一个模块 = 一个分支。不按原子概念建（防分支爆炸）。
- **命名**：`feynman/lab-<模块名>`（如 `feynman/lab-auth`、`feynman/lab-数据库索引`）。
- **适用范围**：仅当学习目标是有本地仓库的代码类学习（github_repo / 本地仓库路径）。纯概念学习（历史/文学）不建分支。

### 3.2 自动创建/切换流程（含安全阀）

```
进入某模块学习（节点3 之后、该模块教学循环之前）
  ├─ 1. 确认场景四态（§2.1）→ 非学习态且非片段 → 跳过分支机制
  ├─ 2. git status 检查工作树
  │     ├─ 干净 → 继续
  │     └─ 有未提交改动 → 先 commit 到当前分支（留痕）或提示用户处理
  │          ——绝不带脏状态切分支
  ├─ 3. 分支 feynman/lab-<模块> 是否存在？
  │     ├─ 是 → git checkout 切过去（复习/继续）
  │     └─ 否 → git checkout -b 创建
  └─ 4. 模块内实验/大作业都在该分支，每次实验 = 一次 commit（留痕）
```

### 3.3 生命周期闭环
- 切下一个模块 → 直接切新分支（当前分支原地存档，不动它）
- 全部模块学完 → 回 main → 问用户：**lab 分支保留为存档 / 合并 / 删除**
- 合并到 main 仅限**自建学习 repo**（用户自己的仓库）；学习副本不合并（本地留痕即可）

### 3.4 push 约束（铁律）
- **绝不** push/merge 到上游原项目或任何他人仓库
- 自建学习 repo：可 push 到用户自己的远程学习 repo（用户明确确认后）
- 学习副本：本地分支 commit 留痕，不 push

## 4. 模块级大作业（动手实验型）

### 4.1 与概念级 PRACTICE 的关系（两层并存，不冲突）

| 层级 | 归属 | 内容 | 状态 |
|---|---|---|---|
| 概念级练习 | 每个知识点 | 原有 PRACTICE（轻量/重量按相对位置） | **保留不动** |
| 模块级大作业 | 每个模块 | 重量级综合动手实验 | **新增** |

### 4.2 作业分配（规则 B）
- **模块计划阶段（节点3）标注**：每个模块声明 `大作业：有（轻量/重量）` 或 `大作业：无`。
- 判定依据：模块内容是否有可动手的实验场景 + 该模块目标深度非最浅级。
- **不要求每个知识点有作业**，避免硬出作业。
- 无大作业的模块：仍建分支（规则 A 统一），分支上放 NOTES.md 学习记录。

### 4.3 作业形式（按场景四态区分重量）

| 场景 | 大作业形式 |
|---|---|
| 学习副本 / 自建学习 repo | 重量：加小功能、重构小块、改核心逻辑看整体行为（隔离在分支） |
| 工作区项目 | 轻量：加 log、注释掉调用看报错、改配置值、加断言追踪路径 |
| 临时片段 | 重量自由（现场造最小示例，随便改） |

### 4.4 作业模板（预测 → 验证闭环，趣味性来源）

```
【模块大作业】<模块名>
- 作业目标：{要达成的效果，一句话}
- 改动内容：{改哪个文件/哪行，改成什么}
- 预测：{我猜改完会……，因为……}
- 验证：{运行/静态分析，实际结果}
- 结论：{结果和预测一致吗？学到了什么机制}
```

- 改完跑 → 验证预测 → 反馈（沿用 P7：先反馈对错再推进）
- 答错/预测失败不惩罚 → 变成"啊哈时刻"：差异点 = 对机制的更深理解

## 5. 双轨归档

| 轨道 | 位置 | 内容 | 状态 |
|---|---|---|---|
| 分支 NOTES.md | 学习 repo 内，跟分支走 | 项目上下文内的实验细节（代码 diff、环境信息、作业过程） | 新增 |
| Obsidian 归档 | 个人知识库 `费曼学习/{学科}/{概念}.md` | 概念总结（现有）+ **作业记录子块**（新增） | 增强 |

### 5.1 Obsidian 作业记录子块（追加到每次学习记录条目内）

```
### {YYYY-MM-DD} · {本族词} · 作业
- 作业目标：{...}
- 改动/实验：{改了什么，预测什么}
- 验证结果：{实际结果}
- 结论：{...}
```

### 5.2 NOTES.md 约定（学习 repo 内，agent 按需组织）
- 位置：分支根目录 `NOTES.md`（或 `feynman-notes/<模块>.md`，由 agent 按需组织）
- 内容：模块学习记录 + 实验细节 + diff 摘录 + 环境/运行命令
- 与 Obsidian 的关系：NOTES.md 是"项目上下文内的工作记录"，Obsidian 是"跨项目的个人知识沉淀"，双轨并存、内容可重叠

## 6. 降级方案

| 情况 | 降级动作 |
|---|---|
| 目标不是 git 仓库 / 只读 | 复制到临时目录再改，或降级为临时片段模式 |
| 真实项目 build/run 失败 | ① 选可独立跑的模块/函数做实验 ② 或静态分析预测（加完功能读代码推结果，教练核对） |
| 纯聊天环境无法执行代码 | 口述预测：用户说"我会怎么改、预测什么效果"，教练核对（沿用重量版降级逻辑） |
| 用户不想建分支 | 豁免（默认强制、可豁免），但提醒"改动无留痕" |
| Obsidian 不可用 | 沿用现有：对话输出归档总结，不中断学习 |

---

## 7. 安全约束

1. **内容隔离**：git 分支隔离"改了什么"——学习态任何改动都在 `feynman/lab-*` 分支上，不污染 main。
2. **运行时隔离**：分支**管不住运行时副作用**（写文件/连 DB/调外部 API）——跑实验前确认脚本无副作用，或在本机隔离环境跑；绝不把有副作用的实验直接指向生产资源。
3. **push 铁律**：绝不 push/merge 到上游/他人仓库；只有自建学习 repo 且用户确认后才 push 到自己的远程。
4. **脏状态保护**：切换分支前必查 `git status`，绝不带未提交改动切分支。
5. **工作区保护**：工作区项目只做轻量干预，改动经用户确认。
6. **P5 例外不变**：上下文模式仍走 fast-path。
