# 银行流水核查（四步法）

银行流水核查是 IPO/再融资项目中耗时最高的工作之一：发行人流水动辄几千到几万行，
多家银行格式不统一，全靠人工筛查效率极低、标准不一、易漏异常。本 skill 把核查流程
固化为四步确定性规则，帮你从几万条记录里快速定位"值得看"的那几十条。

核心原则：**透过资金流动看业务实质**。AI 是"雷达"不是"判决书"——定位可疑交易、
发现异常模式，最终判断需结合业务实质与访谈验证。

## 执行总则

- 每步独立可执行，也可按顺序串联成完整核查流水线；用户只要求其中某一步时只做那一步。
- 所有阈值（金额、天数、时段、关键词）默认按下文设定，**用户没提时用默认值并明确告知**；
  用户提供自定义阈值时以用户为准。
- 输出默认落到可读的表格（Excel 或 Markdown 表），标注新增列，不改动用户原始文件（另存新文件）。
- 涉及敏感数据的，先提示脱敏（见「合规底线」）。

## 第一步：多银行流水格式标准化

**目标**：把不同银行的流水统一成同一套字段口径，便于后续筛查与比对。

**处理规则**（对每家银行的流水逐一执行）：
1. 日期统一为 `YYYY-MM-DD`（原文可能是 `2026/4/16`、`20260416`、文本日期等）。
2. 收入、支出拆成两列（原文若只有「借贷」一列，按借/贷或正负号拆分）。
3. 交易对手名称清理：去首尾空格、统一简称（如「XX有限公司」与「XX公司」合并）、
   剔除"（本部）""-分行"等后缀噪声。
   ⚠️ 必须**先枚举去重后的对手方全表、再合并**，不要边跑边匹配——实测出过同一对手方
   在结果里同时存在「安科电子」和「安科电子科技」两种写法，导致同一对手方的往来被拆成
   两摊，R2 高频往来直接漏判。清理完输出一份「对手方名称映射表」备查。
4. 每张表新增「银行名称」标识列 + 「账户名称」列（带身份后缀，见「输出与交付规范」）。

**可直接复用的指令模板**：
> 请将这批银行流水统一为标准格式：①日期统一为 YYYY-MM-DD；②收入和支出分开为两列；
> ③交易对手名称清理（去空格、规范化简称）；④添加"银行名称"标识列。输出合并后的标准流水表。

**输出**：所有银行统一格式后的合并流水表（含银行名称列）。

## 第二步：关联方交易识别

**前置输入**：第一步产出的标准化流水 + 关联方清单（实控人、董监高、主要客户供应商等）。

**处理规则**：
1. 将流水交易对手与关联方清单匹配（含简称/别名模糊匹配，避免漏判隐蔽关联）。
2. 新增两列：「是否关联方」（是/否）、「风险等级」（高/中/低）。
3. 高风险情形：与实控人/董监高的往来、与客户供应商的大额往来、频繁取现、
   关联方之间互转等。
4. 输出时对关联方交易行做视觉高亮（Excel 填充色或 Markdown 加粗）。

**可直接复用的指令模板**：
> 请识别所有与关联方的资金往来，在表中新增"是否关联方""风险等级"两列。高风险情形包括：
> 与实控人/董监高的往来、与客户供应商的大额往来、频繁取现等。输出标注后的流水表。

**输出**：标注「是否关联方」「风险等级」的流水表，关联方交易自动高亮。

## 第三步：异常交易筛查

**前置输入**：标准化流水（可含上一步打标结果）。

**默认筛查规则**（规则码固定为 R1–R4，命中原因里必须带规则码，便于追溯与统计）：

| 规则码 | 规则 | 默认阈值 |
|---|---|---|
| **R1** | 大额取现 | 单笔取现 > **50 万** |
| **R2** | 高频往来 | 同一对手方窗口内累计**非经营性往来** > **100 万** |
| **R3** | 深夜交易 | 交易时间在 **23:00–05:00** |
| **R4** | 敏感摘要 | 摘要命中敏感词表 |

**敏感词表（唯一，R4 与 R2 共用，不要各写一份）**：
`借款`、`往来款`、`往来`、`暂付`、`备用金`
排除正常经营摘要：`货款`、`采购款`、`材料款`、`回款`、`服务费`、`税费`、`工资`、`报销`、`利息收入`。

**R2 口径必须写死，否则同一套数据会算出不同结果（实测踩过）**：
- 窗口边界：**`当前日期 - 对手方交易日期 <= 6` 天**（即含当日在内的 7 个自然日）。
  不要写成"日期差 ≤ 7 天"——那实际是 8 个自然日，会多算一天。
- 统计范围：**跨账户主体合并计算**。即发行人账户和关联企业账户与同一对手方的往来要加总，
  否则会漏掉"发行人付款 → 关联方转手 → 回流"这类体外循环信号。
- 判定对象：只累计**非经营性**往来；货款/采购款等经营往来不计入（否则对主要客户正常回款误报）。

**标注方式**：命中任一规则 → 标「异常」并注明命中项（如 `R2高频往来(7天累计1,800,000元)；R4敏感摘要(往来款)`）；
高风险标红、中风险标黄。规则命中多条的，逐条列出命中原因。

**可直接复用的指令模板**：
> 请筛查异常交易并标注：①单笔超过50万的取现；②同一对手方7天内累计往来超过100万；
> ③交易时间在23:00-05:00；④交易摘要含"借款""往来款"等字样。高风险标红、中风险标黄。

**输出**：红黄标异常交易表，附每笔异常的命中原因。

## 第四步：资金闭环核查

**前置输入**：发行人 + 关键人员 + 关联方的全套流水（多表）。

**处理规则**：
1. 筛选发行人单笔支付超过 **100 万** 的交易。
2. 追踪每笔大额支付后 **7 天** 内，收款方是否有资金转出及其去向。
3. 识别资金是否回流到发行人或关联方账户（体外循环 / 资金回流信号）。
4. 输出「起点 → 路径 → 终点」明细表，形成完整资金链条。

**可直接复用的指令模板**：
> 请核查资金闭环：①筛选发行人单笔支付超过100万的交易；②追踪每笔大额支付后7天内，
> 收款方是否有资金转出及去向；③识别资金是否回流到发行人或关联方账户；
> ④输出"起点-路径-终点"明细表。

**输出**：资金闭环核查表（起点-路径-终点），自动标记回流/体外循环线索。

## 输出与交付规范

**只认这一套模板**，不要每次临时发挥——历史上出现过两套并行模板（一套带「关联关系」列、
一套带「是否异常」+规则码），导致同一批数据跑出不可比的结论。

### 工作簿结构（5 个 Sheet，带序号前缀便于归档排序）

| Sheet | 内容 |
|---|---|
| `01_标准化流水_打标` | 全量流水 + 打标结果（12 列，见下） |
| `02_关联方识别` | 仅筛「是否关联方=是」的行 |
| `03_异常筛查` | 仅筛「是否异常=是」的行 |
| `04_资金闭环` | 资金链条明细 |
| `05_核查结论` | 项目信息 + 指标统计 + 建议追问方向 |

### 01 表字段（唯一字段顺序，不要增删换序）

`银行名称 | 账户名称 | 交易日期 | 交易时间 | 收入金额 | 支出金额 | 对手方名称 | 摘要 |
是否关联方 | 关联关系 | 风险等级 | 命中原因 | 是否异常`

- **账户名称** 必须带身份后缀：`华辰精密（发行人）`、`辰源贸易（关联企业）`——
  没有身份标注，看表的人无法判断这笔是发行人自己的还是关联方的。
- **关联关系** 必填（关联方行）：`实际控制人` / `董监高（财务总监）` / `关联企业（实控人控制）` /
  `主要客户` / `主要供应商`。缺这一列等于放弃关联方核查的核心信息。
- **命中原因** 带规则码：`R2高频往来(7天累计1,800,000元)；R4敏感摘要(往来款)`。
- **是否异常** 二值（是/否），便于统计；不要留空。

### 04 表字段（量化优先，别只写文字路径）

`序号 | 资金链条 | 起点 | 终点 | 金额合计(元) | 步数 | 类型 | 结论`

- `资金链条` 写完整路径：`华辰精密→辰源贸易(200万) → 辰源贸易→张三(150万) → 张三→华辰精密(150万)`
- `金额合计` = 链条各环节金额之和（如 200+150+150 = 500 万），便于评估规模
- `类型`：`资金回流（体外循环）` / `关联方占款` / `大额取现`

### 05 表字段

上半部分：项目、核查日期、数据范围（各银行笔数）、关联方往来笔数、异常交易笔数、
可疑资金链条数、R1–R4 分项计数。
下半部分：**建议追问方向 ① ② ③ ④ ⑤**——写明「哪笔 + 疑点 + 需要核实什么」，
供项目组访谈直接用。这一块是交付价值最高的部分，不可省略。

### 其他

1. 所有分析结果默认作为核查底稿留存；发现问题条目列入待追踪整改清单。
2. 表头填充 `D9E1F2`，关联方行整行 `FFC7CE`，异常行整行 `FFEB9C`；冻结首行 + 开自动筛选。

## 合规底线（每次执行都必须遵守）

1. **数据脱敏**：银行流水是敏感信息，处理前建议脱敏——隐藏账户号后几位、用代号替代真实人名；
   分析完成后提示用户及时清理临时数据。
2. **AI 只做雷达**：定位可疑、发现模式即可，不做最终定性；判断必须结合业务实质、访谈与凭证验证。
3. **保留痕迹**：AI 分析结果留存为核查底稿，问题追踪整改形成闭环。

## 快速开始

用户说「帮我核查这批银行流水」时，按顺序询问/确认三件事即可开跑：
1. 要跑哪几步（默认四步全跑，也可单跑某一步）。
2. 是否有关联方清单（第二、四步需要）。
3. 阈值是否用默认（50万/100万/7天/23-05点）——不提就用默认。
